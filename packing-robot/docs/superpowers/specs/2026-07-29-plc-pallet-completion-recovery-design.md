# PLC 托盘完成判定与未完成会话恢复设计

## 目标

现场托盘只有在 PLC 请求当前托盘的最后一个 `seq`，并且该箱完成完整握手后，才能从 `active` 改为 `done`。重新计算、连接或断开 PLC、停止发送、关闭或重启程序都不得误完成托盘。PLC 窗口启动后应自动恢复最近的未完成托盘。

## 根因

当前发布新计算结果时会调用 `clear_current_session_after_replan()`。该函数删除 `live_stack_session.json`，并把历史中所有 `active` 托盘直接改为 `done`。PLC 窗口启动时只从该会话文件加载托盘，因此新计算后和程序重启后都会丢失未装完托盘。

## 状态规则

- WCS 通过接口 4.3 选定托盘时，将该托盘写为当前会话并在历史中标记为 `active`。
- 新托盘被选定时，不把其它尚未完成的 `active` 托盘改为 `done`。
- 新计算结果发布后保留当前会话和历史状态；计算不是现场装盘完成信号。
- 当前托盘的最后一个序号定义为计划中所有箱子的最大 `seq`。
- PLC 请求该最大 `seq`，且 `send_normal()` 完成整套握手后，才将对应托盘标记为 `done` 并记录 `completed_at`。
- 报警、异常、人工停止、断开连接或进程退出均不改变 `active` 状态。

## 数据流

`PlcSendWorker` 在每箱 `send_normal()` 返回后继续发出 `box_finished(seq)`。控制器比较该 `seq` 与当前计划的最大 `seq`；相等时调用现场会话状态函数完成该托盘。完成函数只更新与当前 `box_unique_id` 相同的历史项，且仅在会话仍指向该托盘时清除当前会话，避免完成事件误伤后来切换的新托盘。

## 启动恢复

PLC 窗口启动和“从会话刷新托盘”统一使用恢复读取：

1. 优先读取有效的 `live_stack_session.json`。
2. 会话缺失、为空或无 `box_unique_id` 时，从 `live_stack_pallets.json` 倒序查找最近的 `active` 托盘。
3. 找到后重建当前会话文件并加载数据库中的完整托盘方案。
4. 只存在 `done` 历史时不自动加载。

## 异常处理

- 历史或会话 JSON 损坏时沿用现有容错读取；无可恢复托盘时保持空界面。
- 完成状态持久化失败时记录日志，不伪造成功状态；PLC 箱体握手结果不回滚。
- 完成旧托盘时若当前会话已切换到另一托盘，不清除新会话。

## 测试

- 新计算发布后的清理函数保留 `active` 会话和历史。
- 选择新托盘不会把旧的未完成托盘改为 `done`。
- 会话缺失时可从最近的 `active` 历史恢复；只有 `done` 历史时不恢复。
- 普通 `seq` 握手完成不改变托盘状态。
- 最大 `seq` 握手完成后对应托盘改为 `done` 并清除匹配的当前会话。
- 最大 `seq` 之前停止或异常时托盘仍为 `active`。
