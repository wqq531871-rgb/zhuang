# 三维系统多判态路径与垛型直判设计

## 目标

在机器人三维系统中保留现有“相机判态”路径，同时新增“垛型直判（无相机）”
路径。操作员通过界面上的“判态路径”开关选择当前流程：

- `camera`：沿用 PLC 相机长宽高入库、后台监听计算 `state` 的现有流程。
- `layout`：不读取、不校验、不写入任何相机尺寸，直接根据当前托盘内每箱的
  落位后 X/Y 平面尺寸写入数据库 `state`。

系统每次启动默认选择 `camera`，避免升级后自动改变现场行为。

## 垛型判定规则

当前托盘由 `box_unique_id` 唯一确定，每箱由 `box_unique_id + seq` 唯一确定。
箱体尺寸使用 `wcs_success_box` 中的计划落位尺寸：

- X 尺寸：`raw_length`
- Y 尺寸：`raw_width`

`pos_x/pos_y` 是放置坐标，严禁参与尺寸比较。判定规则为：

```text
Y > X  -> state=1
X > Y  -> state=2
X = Y  -> state=1
```

X/Y 必须是大于零的有限数值；无效尺寸会令整盘操作失败。

## 数据库事务

新增独立的垛型判态仓储，不复用按 `product_code` 更新的旧仓储。仓储按当前
`box_unique_id` 执行：

1. 开启事务并使用 `SELECT ... FOR UPDATE` 锁定该托盘全部记录。
2. 校验记录非空、`seq` 从 1 开始连续且不重复。
3. 根据每行 `raw_length/raw_width` 计算目标 `state`。
4. 按数据库主键 `id` 更新 `state`。显式选择垛型路径表示该规则是本次权威
   来源，因此允许把旧的相机判态值覆盖为垛型判定值。
5. 全部成功后一次提交；任一失败则整盘回滚。

接口返回托盘 UID、箱数、实际发生变化的行数和逐箱判定结果，便于界面刷新与
日志追踪。重复执行相同托盘是幂等的。

## 界面与切换语义

三维界面“托盘选择”区域新增：

- “判态路径”下拉框：`相机判态` / `垛型直判（无相机）`。
- “应用到当前托盘”按钮。
- 当前路径处理结果标签。

切换下拉框立即改变随后 PLC 任务使用的路径，但本身不清空或改写数据库，避免
误操作历史托盘。选择 `layout` 后点击“应用到当前托盘”会执行整盘直判并刷新
当前三维方案。

WCS 新加载活动托盘时：

- `camera`：保持现有行为。
- `layout`：在自动播放或自动 PLC 下发前自动完成整盘判态；失败时禁止启动
  PLC 任务并显示明确错误。

在 `layout` 模式下手动发送当前托盘前会再次幂等执行整盘判态，确保数据库状态
与当前计划一致。

切回 `camera` 不自动清空已有 `state`。若要重新进行相机判态，应使用现有现场
复位流程清理目标托盘数据；三维界面不提供破坏性批量清空。

## 三维显示

现有三维动作只有“相机尺寸齐全且 state 已就绪”时才在传送带显示箱子。新增
路径参数：

- `camera`：继续要求相机三维尺寸齐全。
- `layout`：只要求 `state` 为 `0/1/2`，不要求 `camera_*`。

列表中的未就绪提示统一为“待判态”，避免垛型路径仍显示“待相机”。

## PLC 下发

PLC 工作者新增判态路径参数：

- `camera`：保持现有顺序，读取并校验 DBW6/8/10，把相机尺寸写库后轮询
  `state`。
- `layout`：仍等待并校验当前 PLC 请求 `seq`，但忽略 DBW6/8/10，不调用
  相机尺寸写库接口，直接读取当前箱数据库 `state` 并按现有 REV 协议下发。

两条路径继续共用 `state=0` 报警、`state=1/2` 正常下发、非法值拒绝、FP/
FP_OVER/DH_OVER 握手和停止逻辑。

## 错误处理

- 当前托盘为空、UID 为空或数据库无记录：不写库，不启动 PLC。
- 尺寸无效、seq 缺失/重复/不连续：整盘回滚。
- 数据库连接或更新失败：整盘回滚，错误信息写界面日志。
- PLC 任务运行期间禁止重复启动；路径选择在该任务创建时固化，运行中改变下拉框
  不会改变已经启动的工作线程。
- 垛型判态成功但重新加载托盘失败：数据库结果保留，界面报告刷新失败，不启动
  自动 PLC。

## 测试

自动测试不连接真实 MySQL 或 PLC，覆盖：

1. `Y>X -> 1`、`X>Y -> 2`、`X=Y -> 1`。
2. 非正数、非数值和无限尺寸被拒绝。
3. 仓储按 UID 锁行、按主键更新并只提交一次。
4. 空托盘、seq 不连续和更新异常会回滚。
5. 重复应用垛型路径保持幂等。
6. UI 默认相机路径，可切换到垛型路径并应用当前托盘。
7. WCS 活动托盘在垛型模式下先写 state 再启动自动 PLC。
8. 相机路径继续写相机尺寸；垛型路径完全跳过相机尺寸写入。
9. 垛型路径在没有 `camera_*` 时仍可显示和下发。
10. 全量 `packing-robot` 测试通过，现有相机路径行为不回归。
