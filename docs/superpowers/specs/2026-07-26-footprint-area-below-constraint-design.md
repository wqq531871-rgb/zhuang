# 「小箱在下」改为「小面积在下」：设计说明

日期：2026-07-26（回归数据更新至 2026-07-27）
状态：阶段一 + 阶段二实现完成，回归已跑完，**等待用户对「达标率约 −1.5pp」这一代价拍板**。
代码尚未提交，仍在 `main` 的工作区。

## 1. 需求

原「小箱在下」约束先用体积/密度曲线算出小箱阈值，只对 `is_small_box` 的箱子生效，
要求其**正下方不得有体积更大的箱子**。

改为：**任一箱子的正下方不得有投影面积更大的箱子**，对**全部箱子**生效。
即投影面积沿栈自下而上单调不减——小面积在下、大面积在上。

配套删除小箱阈值检测与 `is_small_box` 全链路（含输出 JSON 字段）。

### 口径决定（**我按需求文字选的默认，尚未经确认**）

需求只说了「箱子的下方不能有投影面积更大的箱子，且对所有箱子生效」。
下面这几项是实现时必须定但原话没覆盖的，逐条列出来供核对——
其中「相等面积是否通过」和「下方是否只查直接支撑层」两项若要改，实现要动。

| 问题 | 取的默认 |
|---|---|
| 方向 | 面积小的在下（`350×530` 不能放在 `700×530` 上；`700×530` 可跨放在两个 `350×530` 上） |
| 「下方」范围 | 只查直接支撑层（顶面与本箱底面齐平且 XY 投影重叠）；支撑链连续时可传递推出「下方所有箱面积都不更大」 |
| 相等面积 | 通过（「更大」取严格大于） |
| 面积口径 | 原始尺寸 `raw_length × raw_width`，不含放置容差 |
| 配置键 | 新键 `footprint_area_below_enabled`，旧键 `small_box_below_enabled` 由 `ConfigLoader` 映射 |
| 落地范围 | `packing-system/src` 与 `packing-system/packing/src` 两棵树同步 |

面积口径用原始尺寸的理由：放置容差是每边 +2mm，对不同长宽比的箱子会引入伪差——
`300×600` 与 `400×450` 原始等面积（180000），加容差后 `302×602 = 181804 > 402×452 = 181704`，
按含容差口径比会误判违例。另外面积对 90° 旋转不变（`l×w = w×l`），
所以原始口径同时免疫 `layered_oriented` 的朝向改写。

## 2. 为什么达标盘受影响有限：GCP 主路径结构性免疫

默认主算法是 `main_packer: gcp`。GCP 把同底面箱凑成「柱」
（`_build_columns` 按 `sorted((length, width))` 分组），`layered_packer._assemble`
还把整柱的 `length/width` 统一写成柱底面尺寸，因此**同柱内投影面积严格相等**；
柱之间只在 XY 平面并排（`_grid_pack` / `_cpsat_pack_2d` 全部 `z=0`），从不互相堆叠。

所以新约束在 GCP 主路径上恒成立。真正受冲击的是：
残料柱兜底的 beam、baseline/配方路径、救援链、增量实时装箱。

## 3. 实现

### 3.1 约束谓词

`src/utils/helpers.py`

- `footprint_area(item)` —— 原始投影面积。
- `passes_footprint_area_below_constraint(item, point, dims, placed_boxes)` ——
  替换原 `passes_small_box_not_on_larger_constraint`。

`dims`（含容差）只用于 XY 投影重叠判定，与其余约束的几何口径保持一致；
面积比较一律走原始尺寸。面积在内层循环里就地计算而不调用 `raw_dims()`，
避免按「候选点 × 已放置箱」构造临时 dict。

### 3.2 门禁

`src/geometry/constraint_validator.py`：违例类型 `small_box_on_larger` → `footprint_area_below`，
开关参数改名。所有救援器（`rescue/*`、`pool_compactor`）都经此门禁，自动覆盖。

### 3.3 放置层（改 3 处 + 补 3 处原有漏检）

| 位置 | 动作 |
|---|---|
| `packing/placement_validator.py` | `satisfies_small_box_support_order` → `satisfies_footprint_area_order` |
| `packing/beam_search_packer.py` | 开关字段与候选过滤调用 |
| `packing/direct_layer_packer.py` | 调用 + `_group_sort_key` 排序方向（见 3.4） |
| `main/pallet_packer.py::_place_homogeneous_grid` | **新增**预检 |
| `main/pallet_packer.py::_place_topup_rows` | **新增**预检 |
| `packing/incremental_gate.py` | **新增**预检（见 3.5） |

后三处原先只查 `same_size_heavier_below`。旧约束只覆盖 5.5% 的小箱，漏检代价小；
新约束对全部箱子生效，不补会变成「放置层放行 → 整盘门禁拒收 → 整盘白装一次」。

### 3.4 排序方向必须同步翻转（4(a)）

`direct_layer_packer._group_sort_key` 原按 `(-layer_area, …, -底面积, …)` 降序排组，
再由 `_try_pack_pool` 逐组抬高 `current_z`，即「大底面在下」——与新约束正面冲突。

主键改为**原始底面积升序**。因为每组恰好占整数层带，约束退化成
「组底面积沿栈单调不减」，升序即结构性满足，不会出现放置层自相矛盾导致整池
返回 `[]` 退回 beam。其余键顺序原样保留，**同底面积的池排序结果与改造前逐项相同**。

`beam_search_packer._order_items` 的 `base_area_desc` 同理换成 `base_area_asc`（4(b)）：
新约束下先喂大底面箱等于自断后路。策略表长度恒为 5，`restart_idx % len` 映射不变。

**两处排序都跟随开关**：`footprint_area_below_enabled=False` 时主键取常量 0、
底面积策略回到降序，整个排序逐项退回改造前。这是「开关是真开关」的要求，
已由回归实测验证（见 §4）。

### 3.5 增量门禁的完整性

`incremental_pallet_ok` 除检查 `new_box` 自身外，还检查**底面与 `new_box` 顶面齐平的
既有箱**——`new_box` 填进空洞时会成为它们的新支撑者，可能让原本合法的箱新违例。
`tests/test_incremental_gate.py` 的随机等价测试（15000 例）验证增量门禁与整盘门禁判定完全一致。

## 4. 回归结果

### 4.1 三数据集 A/B（旧约束 vs 新约束）

新约束一侧给出重复跑的实测区间；旧约束一侧只有单次采样，读数时要记住它同样带抖动。

| 数据集 | 规模 | 达标盘 | 总盘 | 耗时 | 基线违例盘 → 新 |
|---|---|---:|---:|---:|---|
| `668箱子数据集` | 668 箱 / 8 箱型 / 1 订单 | 11 → 11 **持平** | 11 → 11 | 51 → 49~79s **持平（噪声内）** | 0 → 0 |
| `5000_full_regular_chain` | 5000 箱 / 31 箱型 / 2 订单 | 139 → 138~140 **持平（噪声内）** | 148 → 148 | 3126 → 934~1076s **约 −67%** | 3(达标 1) → 0 |
| `6000_concentrated_3orders` | 5000 箱 / 45 箱型 / 3 订单 | 143 → **138 (−5)** | 177 → 178~179 | 145 → 184~196s **约 +30%** | 18(达标 6) → 0 |
| **合计** | | 293 → **288±1 (−5)** | 336 → 337±1 | 3322 → ~1240s | 21 → **0** |

箱数全部守恒，新约束违例清零；达标率 87.20% → 85.5%±0.3（**约 −1.5pp**）。

**误差棒必须写出来。** 同代码重复跑的实测抖动：

- `5000_full_regular_chain` 达标取到过 138 / 138 / 140（见 §5.2），
  所以先前记的「+1」在噪声里，实际是持平。
- `6000_concentrated_3orders` 达标三次重复跑稳定为 138，那 **−5 是真信号**。
- `668` 达标稳定持平；耗时三次取到 49 / 64 / 79s，跨过了基线的 51s，
  所以先前记的「+25%」也是噪声，实际持平。
- 耗时对机器负载极敏感（`dcon6` 同代码两次 196s vs 350s），跨版本比耗时只能看数量级。

因此整体达标损失几乎全部来自 `6000_concentrated_3orders`；耗时是「最大最慢的数据集
快了约 3 倍、最杂的数据集慢约 30%、小数据集持平」，不是全面变慢。

**代价与数据规整度强相关**：GCP 能全覆盖的规则数据零损失，且提速约 3 倍
（新约束剪掉搜索空间后，进入昂贵救援链的盘从 138 降到 80，
`rescued_from_failed` 反而 1 → 6）；只有最杂的 45 箱型混装数据掉 5 个达标盘。

**这 5 个盘的损失是约束本身的，不是实现没调好。** 把基线里「靠违反新约束才达标」
的盘直接扣掉，得到一个参考值（不是上界——算法可以重排出新的达标盘）：

| 数据集 | 旧约束达标 | 其中违反新约束 | 扣除后参考值 | 新约束实测 |
|---|---:|---:|---:|---:|
| `668` | 11 | 0 | 11 | **11** |
| `5000_full_regular_chain` | 139 | 1 | 138 | **138~140** |
| `6000_concentrated_3orders` | 143 | 6 | 137 | **138（反超 +1）** |

三份数据全部达到或超过该参考值，说明启发式没有额外浪费达标盘。

### 4.2 开关诚实性验证

两棵树都关掉约束时（旧树读 `small_box_below_enabled: false`，新树读
`footprint_area_below_enabled: false`），输出**逐托盘完全一致**（177 盘 / 141 达标，
175.5s vs 176.2s 属噪声）。证明改动是纯增量、没有夹带无条件的行为漂移。

这一次能比出「完全一致」，是因为约束关闭时 CP-SAT 的子问题都在时限内求完了；
约束开启后同一份数据就不再可复现（见 §6 坑 3）。所以这条结论只适用于验证开关诚实性，
不能反过来当作「输出本该逐托盘一致」的依据。

### 4.3 试过但已回退的补救

丢掉的这批盘是 beam 自由堆出的不规则混底面布局（如 `350×800` 层压在 `660×500` 层上），
不是可整层反转的干净栈。试过把 `base_area_asc` 提到策略表前两格（让 GCP 残料
兜底的 `num_restarts=2` 也能用上），只救回 1 个达标盘却多 1 盘、耗时再涨 15s，
已回退。结合 §4.1 的参考值对比（实测达标全部达到或超过参考值），
结论是这部分损失属于约束本身的固有代价。

### 5.1 验收口径（一次修正）

原先写的验收标准是「阶段二输出应与阶段一逐托盘完全一致」。**这个标准不成立**：
CP-SAT 用 `num_search_workers=8` 加时限，`global_column_packer.py` 的注释本身就写着
「固定种子（注：多线程+时限仍有微小波动）」。实测同一份阶段二代码跑两次，
d668 的 11 个盘**全部**布局不同，dcon6 盘数在 178/179 之间跳——布局不可复现是算法固有属性，
拿它判断删除有没有副作用只会得出假阳性（成因见 §6 坑 3）。

改用**确定性验收**：删除动作全部落在数据装载层，这一层没有随机性，可以逐字段比对。

| 检查 | 方法 | 结果 |
|---|---|---|
| 装载层取值 | `temp/ab/loader_equiv.py` 用基线树与新树各跑一遍 `load_boxes`，逐箱逐字段比对 | 三数据集**全部 PASS**：除 `is_small_box` 外每个字段逐箱相同（`volume` 保留且相等） |
| 装载层键序 | 同上但不排序，比 `list(box.keys())` —— 删掉中间列会改变 `to_dict('records')` 的键序 | 键序一致，`volume` 仍在末位；上一行的比对用了 `sort_keys=True`，单靠它盖不住这个口子 |
| 同型剪枝 key | `is_small_box = 体积 < 阈值`，体积 = `l×w×h`，故它是 `(l,w,h)` 的函数；两处 key 本就含 `round(l,w,h,1)` | 实测三数据集共 50 个尺寸组，**0 组**出现同尺寸不同标记 → 该项在 key 里是冗余项，删除不改变任何等价类 |
| 下游消费方 | 全仓扫 `is_small_box`（含 `.js/.html/.vue/.cs`、`packing-robot`、可视化与仿真目录） | **无任何源码消费该字段**；命中只有历史产物 JSON、`.pyc` 与新测试里两处注释 |
| 排序稳定性 | 扫全仓有无对整箱 dict 做字符串化/哈希/全键遍历；`random.Random` 是否都显式播种 | 均无/均是——删一个键不会改变任何排序或随机流 |

装箱结果层面按**聚合指标**验收（盘数 / 达标盘 / 箱数 / mpm 合计），见 §5.2。

### 5.2 阶段一 vs 阶段二（聚合口径）

**抖动基线用重复跑测出来**（同一份配置，重复跑同一份代码）：

| 数据集 | 阶段一（达标盘） | 阶段二（达标盘） | 结论 |
|---|---|---|---|
| `d668` | 11 | 11 / 11 | 稳定，无差异 |
| `dcon6` | 138 | 138 / 138 | 稳定；总盘数在 178/179 间跳，属噪声 |
| `dreg` | **140 / 138** | **138 / 138 / 140** | 两个版本取值集合相同，都是 {138, 140} |

`dreg` 一开始只有「阶段一 140、阶段二 138」这一对读数，看着像删除引入了 −2。
补跑推翻了它：阶段二第三次回到 140；再用**阶段一复原树**（工作树 + 逐一还原
那 6 个阶段二删除点，已核对只有这 6 个文件与工作树不同）重跑，阶段一也拿到 138。

每箱 `volume`/`weight` 相同，只有 `length`/`width` 因容差与旋转不同——这是布局差异，不是装载差异。

## 6. 回归脚手架的三个坑（血泪记录）

脚手架在 `temp/ab/`（`mkcfg.py` 生成配置，`run_ab.sh` 跑双侧，
`run_repeat.sh` / `run_tree.sh` 跑重复对照，`cmp.py` 比聚合+布局，
`loader_equiv.py` 比装载层）。

**坑 1：配置里有两个 `source_file`。** `incremental.source_file`（约第 10 行）在前，
`excel_data.source_file`（约第 132 行）在后。`run_mode: normal` 读的是后者。
用 `count=1` 的正则或按首次匹配替换会改错那一个，而 `run_packing` 找不到数据集时
**静默回退内置默认数据集**——于是"三个不同数据集"的 A/B 实际跑的是同一份数据，
结果三行数字完全相同。`mkcfg.py` 现在定位 `excel_data:` 段后再改，并回显实际生效的
`source_file`；`run_ab.sh` 在非零退出时打印日志尾部。

**坑 2：对照组必须约束语义对齐。** 想验证「改动是纯增量」时，不能拿
「旧代码 + 旧约束开启」对比「新代码 + 新约束关闭」——旧约束对 5.5% 的小箱是真在生效的，
两侧约束条件不同，差异无法归因。正确做法是**两侧都关掉约束**
（旧树读 `small_box_below_enabled: false`，新树读 `footprint_area_below_enabled: false`），
此时输出应逐托盘完全一致。

**坑 3：布局可复现性取决于 CP-SAT 有没有被时限截断，不能当成恒定前提。**
CP-SAT 跑 `num_search_workers=8` + `max_time_in_seconds`。子问题在时限内求到最优时，
结果可复现；被时限截断时，拿到哪个解取决于线程调度，也就依赖**机器负载**。

这两种情况本次都撞上了，而且刚好和约束开关相关：

| 场景 | 表现 |
|---|---|
| 约束**关闭**（§4.2 的对照） | 两棵不同的树各跑一次，输出**逐托盘完全一致**（177 盘 / 141 达标 / 176s vs 175s） |
| 约束**开启**（同一份数据） | 同代码重复跑，盘数 178/179 跳、耗时 184s→196s→350s、布局逐盘不同 |

解释是一致的：新约束收紧了搜索，更多子问题触到时限，于是不确定性显现。
**所以不能预设「输出应逐托盘一致」**——它在约束关闭时成立，在约束开启时必然报假阳性。
约束开启后可用的判据只有聚合指标（盘数 / 达标盘 / 箱数 / mpm 合计），
外加装载层这类无随机性的环节可以逐字段比。

**噪声量级**（同代码同配置重复跑实测）：

- 达标盘：`d668` 与 `6000_concentrated` 稳定；`5000_full_regular_chain` 抖 **±2**（138/138/140）。
- 总盘数：±1。
- 耗时：最大观测到 **1.8 倍**（196s vs 350s）。

判断达标率变化时，单个数据集 ±2 达标盘、±1 总盘都不应当作信号；
要么重复跑取区间，要么只信在重复跑中稳定的那些差异。
