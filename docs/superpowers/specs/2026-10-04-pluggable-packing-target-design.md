# 可切换装箱目标策略设计

## 背景与目标

系统目前已经允许用户在界面选择“指数 192”或装载率
70%/75%/80%/85%/90%，但该选择只改变最终发布状态；主装箱、停止条件和救援
仍然围绕指数运行。

本次调整要让目标选择贯穿整个装箱过程，同时保留既有指数行为：

- 选择指数模式时，现有主装箱、救援、达标判断和输出行为保持不变。
- 选择装载率模式时，指数只计算和展示，不参与选箱、停止、救援、排序或最终成功判定。
- 装载率模式下，当前托盘达到所选装载率后停止装入，随后开启下一托盘。
- 两种模式共用几何摆放和全部物理约束，不复制整套装箱算法。

## 设计原则

采用“共用算法骨架 + 可插拔目标策略”，而不是另写一套装箱器。

目标策略只负责回答下列问题：

1. 一个箱子对当前目标贡献多少。
2. 一个托盘的当前目标值是多少。
3. 当前托盘是否达到目标。
4. 距离目标还差多少。
5. 一批剩余箱子的理论目标总量是多少。

几何可放置性、重量、稳定性、吸盘、平顶、case_group、订单隔离、箱子守恒等
继续由现有组件负责。

## 目标策略

### 指数策略

- 单箱贡献：`min_pack_multiple`。
- 托盘当前值：`mpm_total`。
- 目标值：现有 `PALLET_INDEX_TARGETS` 对应托盘类型的目标。
- 达标规则：当前指数大于等于指数目标。
- 兼容要求：默认模式和历史结果必须保持一致。

### 装载率策略

- 单箱贡献：箱子体积 `length × width × height`。
- 托盘当前值：箱子总体积除以托盘可用体积。
- 目标值：界面所选的 0.70、0.75、0.80、0.85 或 0.90。
- 达标规则：当前装载率大于等于目标装载率。
- 停止规则：达到目标后停止向当前托盘继续装箱。
- 指数处理：继续计算 `mpm_total`、`mpm_target`、`mpm_gap` 和
  `index_status`，仅用于展示和追溯。

装载率使用实际装入箱子的原始体积总和，不使用外接包围盒，也不扣除箱间间隙。

## 架构与数据流

新增一个小型目标策略模块，由配置中的 `success_target` 构造策略对象。主工作流在
分组装箱开始时将策略传给装箱器、候选方案排序和救援器。

数据流如下：

1. UI 将所选模式和阈值写入本次临时 YAML。
2. CLI/WCS 服务从同一 YAML 创建目标策略。
3. 工作流把策略传入主装箱和救援阶段。
4. 主装箱使用策略贡献值与阈值决定当前盘何时停止。
5. 候选方案优先比较达标托盘数量，其次比较托盘数量和尾盘接近目标的程度。
6. 救援阶段只对当前策略下未达标的托盘进行合并、补箱或重排。
7. 输出阶段同时写入目标状态与独立的指数状态。
8. 输出目录、执行顺序、WCS 下传资格继续读取最终目标状态。

## 主装箱调整

现有 Beam Search 与 GCP 保留摆放逻辑，只把硬编码的指数累计和指数目标判断委托给
目标策略。

- Beam Search 的 `stop_when_target_met` 继续存在，但“是否达标”由策略判断。
- GCP 的候选排名仍优先最大化达标托盘数；“达标”改为当前策略的达标定义。
- 精确目标子集选择在指数模式使用指数贡献，在装载率模式使用体积贡献。
- 达标后的最小溢出在指数模式表示指数溢出，在装载率模式表示超过目标的体积。
- 所有箱子仍必须进入某个托盘；达到目标后未装入的箱子进入后续托盘，不得丢弃。

## 救援调整

不复制救援链。救援器接收同一个目标策略，并用策略提供的当前值、缺口和达标判断
替代直接读取 `mpm_status`、`mpm_total` 和 `target_mpm`。

- 指数模式沿用原指数救援参数和行为。
- 装载率模式只救援装载率未达标盘。
- donor/receiver 的选择依据装载率缺口，不依据指数缺口。
- 合并或重排方案只有在箱子守恒、物理门禁通过，且目标结果不变差时才接受。
- 无法达到目标的剩余箱仍生成尾盘，并标记为最终失败。

确实只适用于指数的诊断和优化可以在装载率模式跳过，但不得阻止通用救援步骤运行。

## 增量模式

增量模式的保留盘与重排盘必须依据当前目标策略：

- 指数模式保留指数达标盘。
- 装载率模式保留装载率达标盘，即使指数未达标。
- 未达标盘中的箱子与新增箱合并后，继续使用同一目标策略重排。

这与现有“只在最终报告应用装载率”的临时兼容行为不同，实施后应由策略贯穿两阶段。

## 输出兼容性

每个托盘继续输出：

- `mpm_total`、`mpm_target`、`mpm_gap`、`index_status`：真实指数信息。
- `fill_rate`：真实装载率。
- `goal_mode`、`goal_threshold`、`goal_value`、`goal_status`、
  `final_status`：当前目标信息。
- `mpm_status`：为兼容现有输出分桶、执行和 WCS 消费者，继续映射为最终目标状态。

界面的指数卡始终显示 `index_status`，最终状态区域显示当前目标及其结果，避免出现
“指数 180/192 但指数卡显示 SUCCESS”的歧义。

## 错误处理

- 非法目标模式或非允许的装载率档位在启动时明确报错。
- 托盘尺寸或体积缺失时，装载率模式不得静默按 0 继续，应报告数据错误。
- 单箱体积超过托盘体积时仍由现有几何门禁处理，不单独绕过。
- 目标策略不得改变原始箱子尺寸、位置或订单字段。

## 测试与验收

### 指数零回归

- 现有完整算法测试必须通过。
- 固定输入在指数模式下的托盘数、箱子归属、位置和指数状态与修改前一致。

### 装载率行为

- 构造指数未达标但装载率达标的托盘，主流程、输出、执行资格和 WCS 均判定成功。
- 构造指数达标但装载率未达标的托盘，最终判定失败并进入装载率救援。
- 达到目标装载率后停止当前盘，剩余箱子进入下一盘。
- 五个允许档位都按包含边界判定。
- 救援不读取指数状态决定 donor/receiver 或接受方案。

### 系统门禁

- 普通 Excel、WCS 接口和增量模式都覆盖两种目标策略。
- 箱子无遗漏、无重复，case_group 和订单隔离不变。
- 几何、重量、稳定性、吸盘和平顶约束继续通过。
- 输出 JSON 和 Excel 同时保留真实指数与最终目标信息。

## 非目标

- 不改变界面已有六个选项。
- 不引入新的装载率档位。
- 不改变托盘尺寸、体积定义或物理约束。
- 不为装载率模式复制一套独立装箱算法。
- 不删除指数字段或历史消费者依赖的兼容字段。
