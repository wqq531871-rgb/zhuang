# 「托盘整体限重」约束说明

> 甲方 2026-09 需求：现场运行时部分托盘整垛重量超过 1000kg，需要加限重约束。
> 面向工程人员：讲清楚约束口径、判定规则、实现位置、开关与实测影响。

## 1. 需求口径

- **整盘（整垛箱子）重量和 ≤ 1000kg**。重量取箱子的 `总重量` 字段
  （Excel）/ `weight` 字段（WCS 接口），缺字段按 0 计。
- 托盘自重不计入（约束的是「垛型」，与甲方措辞一致）。
- 对**所有托盘**生效，不区分达标盘 / 尾盘 / 守恒兜底盘。
- Excel 文件与 WCS 接口两种计算方式**同时生效**（共用同一装箱核心）。
- **唯一豁免**：单箱本身就超过 1000kg。这类箱在任何托盘上都不合法，重排也
  救不了；拦下来会让「绝不丢箱」的守恒兜底无路可走。因此单箱盘放行，并在
  运行开始时打印告警，请现场核对重量数据。

## 2. 为什么这条约束的实现方式和别的约束不一样

限重是 `Σ weight(箱) ≤ W`，**可加且与几何无关**——只取决于「哪些箱在盘上」，
与位置、朝向、堆叠方式无关。本项目其它硬约束（支撑率、间隙、重心、平顶不缺角）
全部是位置相关的。三条推论直接决定了实现：

1. **可精确入模**。线性可加 ⇒ 能作为一条线性约束直接写进 GCP 的
   Set-Partitioning ILP 与 CP-SAT 子集选择模型。因此**不是**「造完盘再拒收」，
   而是求解器在「重量可行」的解空间里直接找最优解——达标率的损失恰好等于
   数学上不可避免的下界。几何约束做不到这点（所以平顶只能靠生成侧启发式收紧
   + 门禁拦 + 拆顶兜底）。
2. **下闭**。合法箱集的任意子集仍合法 ⇒ 拿掉箱子永远不会破坏限重，因此
   **不需要任何拆顶 / 降级补救机制**（与平顶约束正相反）。
3. **与指数目标的竞争强度可量化**。达标需 192 指数、限重 1000kg ⇒ 只有当盘内
   平均 **ρ = 重量 / 指数 > 1000 / 192 ≈ 5.21 kg/指数** 时，限重才可能吃掉达标率。
   ρ 低于该阈值时，限重对达标率零影响。

## 3. 实现结构

| 层 | 位置 | 职责 |
|---|---|---|
| 单一事实来源 | `src/geometry/weight_limit.py` | 取限重值、求和、整盘校验、「本组是否可能触发」判定 |
| 入口告警 | `src/main/workflow.py` | 列出单箱即超限的箱子（数据异常） |
| 柱形成 | `layered_packer._ffd_columns`、GCP 的 `_balanced_columns` / `_concentrated_columns` | 柱重 ≤ 限重（柱是整体上盘的最小单位，超重柱必须在凑柱时切断） |
| 柱类型键 | GCP `_build_pools` | 并入柱重 ⇒ pattern 总重有确定值 ⇒ 精确剪枝 |
| 类型合并 | GCP `_merge_weight_classes` | 并入柱重会让类型数翻倍、枚举空间可能超阈而退贪心；合并「重量最接近」的类（上界取组内最大）压回可负担范围 |
| 模式枚举 | GCP `_enumerate_patterns` | pattern 总重超限即剪掉 |
| 大组贪心 | GCP `_same_type_boards` / `_greedy_mixed_boards` | 逐柱累加不超限 |
| CP-SAT 子集 | GCP `_select_target_subset_cpsat` | 线性约束 `Σ w_i·sel_i ≤ W` |
| beam 放置 | `beam_search_packer._pack_with_beam_search` | 按状态逐箱累加，超限的箱留给下一盘 |
| 增量门禁 | `packing/incremental_gate.py` | 救援器塞箱的快速等价路径 |
| 整盘门禁 | `geometry/constraint_validator.py` | 最终安全网（`pallet_overweight` 违规项），覆盖全部救援链、择优棘轮与最终输出 |

### 「本组是否可能触发」短路（零回归的依据）

生成侧的限重逻辑只在**可能触发**时启用。判据是单盘重量的**可靠上界**：把箱按
kg/m³ 降序装满托盘容积（分数背包）——任一盘的箱体积和必 ≤ 托盘容积，故该值
是任何一盘重量的上界。上界 ≤ 限重 ⇒ 本组恒不可能超限 ⇒ 柱类型键、模式枚举、
贪心装盘全部走历史路径。

这不是「测出来没变化」，而是**结构上不可能变化**。实测两个现有数据集：

| 数据集 | 单盘重量上界 | 是否触发 |
|---|---|---|
| 668 规则单订单 | 65.7 kg | 否（远低于 1000） |
| 5000 混杂三订单 | 654.4 kg | 否 |

（上界用分数背包而非「最大密度 × 容积」：5000 数据集里有 4 只密度异常的箱，
粗略算法给出 19.6 吨的无用上界，分数背包给出 654kg。）

## 4. 开关与配置（`config/packing_config.yaml` → `constraints` 段）

```yaml
max_pallet_weight_kg: 1000.0   # 整盘限重（千克）；≤ 0 = 关闭，完全恢复历史行为
```

需要按托盘类型区分限重时，在 `ConstraintConfig` 上扩展成映射即可，当前甲方
只给了单一数值。

## 5. 实测影响

### 5.1 现有数据（重量原值）——零回归

| 数据集 | 限重关 | 限重开 | 逐盘签名 |
|---|---|---|---|
| 668 规则单订单 | 12 盘 / 达标 10 / 最重 55.8kg | 12 盘 / 达标 10 / 最重 55.8kg | **完全一致** |
| 5000 混杂三订单 | 179 盘 / 达标 138 / 最重 230.6kg | 179 盘 / 达标 138 / 最重 230.6kg | **完全一致** |

两个数据集的箱子都太轻，单盘重量上界远低于 1000kg，约束被短路，方案逐盘
（状态 / 指数 / 箱 id 集合）完全相同，耗时也不变。

### 5.2 合成重数据（668 重量整体放大）——约束真正生效时的代价

放大倍数决定 ρ = 重量/指数。**ρ > 5.21 kg/指数时 192 达标在 1000kg 内物理不可能**。

| 倍数 | ρ (kg/指数) | 限重关（基线） | 限重开 | 说明 |
|---|---|---|---|---|
| ×20 | 4.83 | 12 盘 / 达标 **10** / 最重 **1116.5kg**（4 盘超限） | 12 盘 / 达标 **10** / 最重 **989.9kg** / **0 盘超限** | **达标率零损失**，仅把 4 个超限盘重新配平 |
| ×30 | 7.25 | — | 16 盘 / 达标 0 / 最重 999.3kg / 0 超限 | ρ 越过阈值，达标在物理上不可能；每盘填到 99.9% 限重 |
| ×50 | 12.08 | — | 26 盘 / 达标 0 / 最重 998.9kg / 0 超限 | 同上；无单箱退化盘，守恒 OK |

×20 是最有说服力的一档：基线有 4 个达标盘超重（1116.5 / 1095.9 / 1095.9 /
1047.0 kg），开启限重后**一个达标盘都没丢**，只是把箱子重新分配到 990kg 以内。
这正是「精确入模」的价值——把限重放进 ILP 的可行域，求解器自己找配平方案；
若改成「造完盘再拒收」，这 4 个盘会直接掉成尾盘。

达标率对实现方式极其敏感，中间踩过两个坑（都已修）：

| 实现方式 | 668 ×20 达标盘 |
|---|---|
| 柱重直接并入类型键 | 7（类型 5→10、枚举空间 3.1万→298万 超阈 ⇒ 被迫退贪心） |
| 退回「按最大柱重保守剪枝」 | 8（同类型柱重 45.5～90.4kg，保守放大近 2 倍） |
| **自适应合并最接近的重量类** | **10（= 基线，零损失）** |

### 5.3 耗时

- 现有数据（约束短路）：耗时不变。
- 668 ×20：78s，与基线同量级。
- 668 ×30：359s（病态档：大量 pattern 因超限被剪，平顶模式的 CP-SAT 完美平铺
  重试次数上升）。现场若真出现这种密度，需要放宽指数目标或调 `_CPSAT_*` 时限。

## 6. 已知边界

- 现有两个数据集的箱子都很轻（668 满盘约 46kg、5000 满盘上界 654kg），
  约束不触发，因此**现有数据的达标率与耗时完全不变**。约束的实际影响要用
  现场真实重量数据复测。
- 箱子重量缺失（Excel 无 `总重量` 列 / 接口无 `weight`）时按 0 计，等价于
  不限重。现场若发现某批数据限重不起作用，先查重量字段是否落库。
- 单箱超过 1000kg 的数据异常箱会单独成盘并豁免限重，运行开始时有告警。
- 重箱会让托盘装得稀疏。真实箱型混合（668 ×30/×50）实测不会退化：每盘仍能
  填到 99.9% 限重、无单箱盘。但**单一超重箱型**的极端情形（如单箱 300kg、
  一盘只放得下 3 只）会让整盘重心偏出托盘中心 1/3 的容差，被既有的重心清理
  逻辑拆盘并退化为单箱盘——这是「重心稳定」与「限重」两条硬约束的固有冲突，
  不是限重本身的缺陷。现场若出现该量级的重箱，需要与甲方确认重心容差口径。
- ρ > 5.21 kg/指数 时 192 达标在 1000kg 内数学上不可能，输出全是尾盘。这不是
  算法退化；若现场数据真落在该区间，需要甲方在「限重」与「指数目标」之间取舍。
