# 独立执行顺序规划

该功能位于 `src/execution/`，在装箱算法完成最终坐标规划之后运行。它不调用或修改
GCP、beam、配方、救援链等装箱逻辑，也不改变原始 `packing_plan_*.json`。

## 目标

- 固定每个托盘的最终箱子集合、相对布局、尺寸和朝向；在托盘剩余空间内整体居中垛型。
- 保证直接支撑箱先放置。
- 保证箱体和已保存吸盘姿态的预放下降、斜向推进、最终下降及抬升扫掠空间可用。
- 所有托盘使用同一套有向空间阶梯波，从远端原点向机器人侧确定性扩散。
- 输出保留原装箱报告的业务字段，并更新执行顺序、绝对 XY 坐标和执行高度字段。

## 机械臂运动模型

现场机械臂位于托盘 `x_max_y_max` 一侧。目标箱最终位置为 `P=(x,y,z)`，预放位置为：

```text
P_pre = (x + approach_offset_x_mm,
         y + approach_offset_y_mm,
         z + approach_z_clearance_mm)
```

每次放箱按以下四段名义路径检查：

1. 箱体和吸盘在 `P_pre` 上方垂直下降。
2. 箱体和吸盘从 `P_pre` 沿 `-X/-Y` 斜向推进到目标 XY。
3. 箱体在目标位置完成最终下降并落到直接支撑面。
4. 放箱后吸盘在目标位置垂直抬升。

当前 X/Y 偏移均为 `20 mm`，斜向距离约为 `28.3 mm`。该模型验证箱体和吸盘的
轴对齐外廓，不替代机器人控制器的 IK、关节限位、完整连杆碰撞和速度规划。

## 依赖与排序规则

每个托盘先建立有向依赖图：

1. 直接支撑箱指向上层箱；接触面积按 `original_*`/`raw_*` 实物尺寸判断，
   不把算法用于留间隙的膨胀占位尺寸当作真实支撑。
2. 对支撑层级更高的箱 U，如果其顶面明显高于待放低层箱 L，并进入 L 的箱体局部
   前沿或吸盘朝 `+X/+Y` 的退出扫掠区，则增加 `L -> U`。局部前沿按实物箱体投影
   判断，水平间隙小于等于 `side_neighbor_clearance_mm` 时也建立依赖，不受吸盘矩形
   是否内缩影响。这只延迟会阻挡后续局部路径的上层箱，不要求整层完成。
3. 如果先放箱 B 会阻挡箱 A 的箱体下降扫掠空间，则增加 `A -> B`。
4. 如果先放箱 B 会阻挡箱 A 已保存的吸盘矩形下降，则增加 `A -> B`。
5. 如果最终箱 B 会阻挡箱 A 的预放下降、斜向推进或目标位置最终下降，则增加
   `A -> B`。箱体和吸盘分别使用自己的推进安全包络。
6. 使用 Kahn 排序确认静态依赖图无环，再按有向空间阶梯波建立稳定的正向偏好。
   每一步都从尚未放置箱子的偏好头开始扫描，只选择硬依赖已满足、当前开放方向
   合法且选择后剩余箱仍可完成的第一个箱子。
7. 剩余可完成性检查固定已经放置的前缀，从剩余集合反向剥离。候选必须是剩余 DAG
   的 sink，并且相对固定前缀和其它剩余箱，同高或更高邻箱占用方向不超过配置上限。
8. 最终结果在居中前、居中后分别逐箱回放支撑、局部抬升/退出走廊、垂直扫掠、
   三段接近路径和开放方向
   门禁。关闭开放方向门禁时只跳过方向 blocker 和剩余可完成性检查，不跳过机械臂
   路径门禁。

有向空间阶梯波分别按 X/Y 进度聚类得到 `x_rank`、`y_rank`，再计算：

```text
spatial_ring = max(x_rank, y_rank)
wave = spatial_ring + support_tier
排序键 = (wave, spatial_ring, x_rank, y_rank, support_tier, stable_index)
```

第一物理层的 `support_tier=0`，因此从 `x_min_y_min` 空间环严格向外扩散。上层箱把
支撑层级加入波次，同一波次优先完成更靠近远端的空间环，形成“远端逐步升高、外圈
同步铺底”的阶梯形。所有托盘无条件使用这一套排序，不再进行逐层/阶梯模式分类。

空间波是同等安全候选中的软优先级，不是硬约束。支撑、机械臂扫掠和开放方向门禁
需要时允许最小局部偏离，避免为了保持视觉顺序而生成碰撞或不可完成路径；规划器会
在 warning 中记录偏离的箱号与原因。若硬依赖成环，完整门禁路径会失败；是否继续
生成受控降级顺序由 `force_publish_on_gate_failure` 决定，不回退旧逐层顺序。

## 支持的原点

- `x_min_y_min`（默认）
- `x_min_y_max`
- `x_max_y_min`
- `x_max_y_max`

坐标语义与算法报告一致：原点位于托盘底面，x 为长方向，y 为宽方向。
现场机械臂位于 `x_max_y_max` 一侧时应保持 `origin: x_min_y_min`，使波源位于远端。
其它原点只用于不同机器人站位或离线验证，修改前必须同时确认实际推进方向。

## 垛型居中和当前最高高度

执行顺序确定后，规划器按所有箱子在托盘底面的实物 XY 投影包络计算整体平移量：

```text
shift_x = (右侧余量 - 左侧余量) / 2
shift_y = (上侧余量 - 下侧余量) / 2
```

原垛型从 `x_min_y_min` 开始时，上式等价于把远端剩余空间分别除以 2。某一轴的
垛型投影已经占满托盘、该轴总剩余空间不大于几何容差时，该轴平移量固定为 `0`。
平移同时更新 `position.x/y` 和四个绝对 `suction_rect_*` 坐标，`position.z`、箱子
相对位置、尺寸和朝向不变。依赖绝对 XY 的 `robot_depth` 和 `robot_depth_band` 也按
原 `robot_reference` 重新计算。平移后重新执行边界、支撑、局部抬升/退出走廊、
垂直下降、定向推进、最终下降和开放方向门禁。完整门禁失败时按下文“失败策略”
决定拒绝发布或生成受控降级顺序。

规划器再按最终 `seq` 顺序给每个箱子增加 `stack_height_before`：

```text
stack_height_before(i)
= max(position.z + 实物箱高)，范围为 seq < i 的所有已放箱
```

第一箱的值固定为 `0.0`。该字段表示放置当前箱之前的垛型最高顶面，单位与现有
坐标一致为毫米，不包含机械臂额外安全余量。

## 配置

是否启用该功能以及规划参数统一从 `config/packing_config.yaml` 的
`execution_sequence` 段读取：

```yaml
execution_sequence:
  enabled: true
  origin: x_min_y_min
  coordinate_tolerance_mm: 0.000001
  box_xy_clearance_mm: 0.0
  suction_xy_clearance_mm: 0.0
  suction_z_clearance_mm: 0.0
  approach_offset_x_mm: 20.0
  approach_offset_y_mm: 20.0
  approach_z_clearance_mm: 20.0
  approach_box_xy_clearance_mm: 0.0
  approach_suction_xy_clearance_mm: 0.0
  require_suction_pose: true
  max_occupied_directions: 2
  side_neighbor_clearance_mm: 5.0
  side_height_tolerance_mm: 2.0
  preserve_open_direction: true
  force_publish_on_gate_failure: true
  max_sequence_search_seconds_per_pallet: 1.0
  scan_column_tolerance_mm: 5.0
```

- `enabled: true` 时，`run_packing.py` 在原装箱报告保存后自动生成 execution、
  WCS cases 和 WCS map。
- `enabled: false` 时只生成原装箱报告和托盘汇总 Excel。
- 独立命令的输入和输出路径属于单次任务参数，继续通过命令行指定，不写入公共配置。
- 原点和数值参数默认使用配置文件；独立命令的显式参数仅覆盖本次运行。
- `--xy-clearance-mm` 会同时覆盖箱体和吸盘 XY 余量；也可分别使用
  `--box-xy-clearance-mm`、`--suction-xy-clearance-mm`。
- `--allow-missing-suction` 和 `--require-suction-pose` 可临时覆盖
  `require_suction_pose`。

### 参数解释

#### `coordinate_tolerance_mm`

几何计算容差，用于判断箱子是否位于托盘底面、上下箱顶面和底面是否接触、两个
矩形是否存在有效重叠，以及箱子是否越过托盘边界。默认值 `0.000001 mm` 只用于
吸收浮点计算误差，不是机械臂定位误差。通常应保持默认值；把它设置成数毫米可能
导致悬空、微小越界或微小重叠被误判为合法。

#### `box_xy_clearance_mm`

箱体垂直下降路径的 XY 安全包络。规划器会把目标箱的实物矩形向 X/Y 四周分别
扩大该数值，再检查已经放置的箱子是否进入下降通道。例如设置为 `10`，表示箱体
每一侧增加 10 mm，检查矩形的总长度和总宽度各增加 20 mm。该值可覆盖箱体摆动、
抓取偏移和部分机械臂误差；值越大，约束越严格，也越容易产生无法换序解决的依赖环。
`0` 仅表示当前布局不增加箱体包络；若现场需要 2 mm 间隙，必须由上游布局产生至少
对应的物理间隙，不能靠调整执行顺序绕过。

#### `suction_xy_clearance_mm`

吸盘垂直下降路径的 XY 安全包络。规划器以箱子保存的
`suction_rect_x_min/x_max/y_min/y_max` 为基础，向四周分别扩大该数值。它主要用于
覆盖吸盘边缘、法兰、管路、腕部外廓和 XY 定位误差。设置为 `10` 同样表示吸盘
矩形每一侧增加 10 mm。它与 `box_xy_clearance_mm` 分开配置，因为箱体外廓和机械臂
末端执行器外廓通常不同。

#### `suction_z_clearance_mm`

吸盘下降到目标箱顶面附近时要求保留的高度余量。假设目标箱顶面为 500 mm，配置
为 `20`，则吸盘 XY 扫掠区域内已经放置的其它箱子顶面必须不高于约 480 mm；高于
该高度会被视为遮挡。该值用于覆盖 Z 定位误差、吸盘压缩量和末端执行器低于理论
姿态的外廓。值越大，允许靠近目标箱的已放高箱越少。

#### `require_suction_pose`

是否强制要求每个箱子具有完整、有限且有效的四个 `suction_rect_*` 字段。设置为
`true` 时，任一箱子缺少吸盘矩形都会拒绝生成该执行方案。设置为 `false` 时，缺少
吸盘字段的箱子仍检查直接支撑和箱体下降路径，但跳过该箱子的吸盘下降路径检查。
现场机械臂方案建议保持 `true`。

### 定向推进参数

- `approach_offset_x_mm` / `approach_offset_y_mm`：目标位置到预放位置的 X/Y 水平
  分量。当前交付值均为 `20 mm`，表示机械臂从目标的 `+X/+Y` 一侧开始约 `28.3 mm` 的
  斜向推进。应按现场实际推进位移标定；它们描述路径长度，不是安全余量。
- `approach_z_clearance_mm`：预放位置相对目标底面的额外 Z 抬高量。当前交付值为
  `20 mm`。若现场先在更高处推进再最终下降，应填写实测高度，规划器会据此扩大
  推进和最终下降的 Z 扫掠区间。
- `approach_box_xy_clearance_mm`：箱体在预放下降、斜向推进和最终下降阶段每侧增加的
  XY 安全包络。默认 `0`，现场出现箱体推进擦碰时按实测摆动误差逐步增加。
- `approach_suction_xy_clearance_mm`：吸盘在预放下降和斜向推进阶段每侧增加的 XY
  安全包络。当前交付值为 `0`；现场完成吸盘边缘、腕部外廓和推进阶段误差测量后，
  再按实测上界增加。

推进扫掠使用移动矩形与静态矩形的精确斜向相交测试，不用起终点外接矩形代替，
避免把斜线路径两侧实际不会经过的区域误判为阻挡。

### 防包围参数

- `max_occupied_directions`：目标箱放置时，允许同高或更高邻箱占用的最大方向数。
  方向固定为 `x-、x+、y-、y+`，现场建议保持 `2`。
- `side_neighbor_clearance_mm`：判定侧面邻箱以及局部抬升/退出走廊时允许的最大水平
  间隙，间隙小于等于该值时纳入依赖。局部低层前沿使用实物箱体投影判断，吸盘
  矩形只用于定向退出扫掠，因此吸盘内缩不会放过紧邻箱体。
- `side_height_tolerance_mm`：比较邻箱和目标箱顶面高度时使用的容差。明显低于目标
  箱顶面的邻箱不计入硬包围方向。
- `preserve_open_direction`：是否启用防包围硬门禁。现场执行应保持 `true`；设为
  `false` 时只关闭该门禁；支撑、垂直扫掠、定向推进和有向空间波仍然执行。
- `force_publish_on_gate_failure`：完整路径门禁失败时是否继续生成执行三件套。本版
  现场联调设为 `true`。降级仍保留箱子守恒、唯一连续 `seq`、托盘边界、配置要求的
  完整吸盘位置、直接支撑、高度感知局部走廊、垛型居中和 `stack_height_before`，
  只绕过垂直/斜向扫掠、开放方向及其最终回放。控制台会记录托盘 ID 和原始门禁错误。
- `max_sequence_search_seconds_per_pallet`：每个托盘完整防包围规划的时间预算，覆盖
  邻接预计算、正向选择和残余反向剥离。超时不会放宽安全规则，也不会静默输出
  三面或四面包围的 execution 方案。
- `scan_column_tolerance_mm`：X/Y 进度的锚点聚类容差。相对执行原点的坐标前沿差不
  超过该值时视为同一级；聚类以锚点为基准，不做链式扩张。该参数只决定空间环的
  排序偏好，不替代 `coordinate_tolerance_mm` 的几何判断。

有向空间波使用 `(wave, spatial_ring, x_rank, y_rank, support_tier, stable_index)` 作为
正向键。坐标等级相同的箱子保持输入顺序，不再用未聚类的精确坐标打破平局。

支撑、箱体/吸盘下降路径和开放方向属于安全约束，必要时可产生最小局部扫描偏离。
一次调度成功后至多输出一条偏离 warning，包含去重后的总数和最多 8 项预览；每项
标明 `expected`、`selected` 以及 `hard_dependency` 或 `open_direction`，因残余不可
完成而跳过局部合法候选时还会标明 `lookahead=true`。规划器不再输出逐层/阶梯模式
分类日志。

## 一条命令生成全部方案

正常运行时只需要执行：

```powershell
python code/run_packing.py --config code/config/packing_config.yaml
```

同一时间戳下始终生成：

- `packing_plan_<timestamp>.json`：原始装箱方案，箱子顺序保持算法输出顺序。
- `packing_plan_summary_<timestamp>.xlsx`：原方案的托盘统计表。

当 `execution_sequence.enabled: true` 时，还会自动生成：

- `packing_plan_<timestamp>_execution.json`：机械臂最终执行方案；垛型按轴居中，
  `packed_items` 使用最终顺序，每箱包含 `stack_height_before`。
- `packing_plan_<timestamp>_execution_wcs.json`：WCS 接口 2 的 case 数组，`seq` 使用
  新执行顺序，不包含 `stack_height_before`。
- `packing_plan_<timestamp>_execution_wcs_map.json`：机器人侧留存映射，保存
  `box_unique_id -> 执行托盘坐标与顺序`，不包含 `stack_height_before`。

当 `execution_sequence.enabled: false` 时，不生成以上三个 execution 文件。

### 输出接口使用哪个文件

调用 WCS 的“规划订单输出”接口
`/adaptor/api/wcs/sendpalletplanresult` 时，应把
`packing_plan_<timestamp>_execution_wcs.json` 的完整 JSON 数组作为请求体发送。

- 不要把原始 `packing_plan_<timestamp>.json` 发给该接口，它不是接口 2 的字段结构。
- 不要把 `_execution.json` 直接发给 WCS；它是机器人侧完整坐标方案。
- 不要把 `_execution_wcs_map.json` 发给 WCS；该文件必须留在机器人侧，供接口 3/4
  根据 `box_unique_id + seq` 查找目标坐标和吸盘姿态。

## 独立重跑命令

已经存在原装箱 JSON，需要单独重新生成执行顺序时，仍可使用：

```powershell
python code/run_execution_planning.py `
  output/packing_plan_20260712_092845.json `
  --output output/packing_plan_20260712_092845_execution.json `
  --config code/config/packing_config.yaml `
  --origin x_min_y_min
```

同时输出 WCS case 数组：

```powershell
python code/run_execution_planning.py `
  output/packing_plan_20260712_092845.json `
  --output output/packing_plan_20260712_092845_execution.json `
  --wcs-output output/packing_plan_20260712_092845_execution_wcs.json
```

只要指定 `--wcs-output`，CLI 还会自动输出
`packing_plan_20260712_092845_execution_wcs_map.json`。该 sidecar 保存
`box_unique_id -> 执行托盘坐标与顺序`，机器人服务用 `seq-1` 定位到按执行顺序排列的
`packed_items`，取得箱子 ID、目标坐标和 `suction_*` 字段。可用
`--wcs-map-output` 指定其它路径。该文件不包含仅供装箱结果留存的
`stack_height_before`。

加入现场测得的安全包络：

```powershell
python code/run_execution_planning.py INPUT.json `
  --xy-clearance-mm 10 `
  --z-clearance-mm 5
```

- `--xy-clearance-mm` 同时扩大箱体和吸盘 XY 扫掠矩形。
- `--z-clearance-mm` 要求吸盘下降到箱顶时与已放箱顶保留对应高度余量。
- 所有容差必须是有限且非负的数字；`NaN`、`Infinity` 和负数直接拒绝。
- 默认要求每箱已有完整 `suction_rect_*` 字段。
- `--allow-missing-suction` 仅供不启用吸盘约束的数据使用，现场机械臂方案不建议开启。

## 输出保证

执行报告保留原报告的根字段、托盘业务字段、箱子集合、尺寸、朝向和相对布局。
允许变化的执行字段只有 `packed_items` 数组顺序、`seq`、`position.x/y`、四个
`suction_rect_*` 绝对 XY 坐标、重新计算的 `robot_depth`/`robot_depth_band`，以及
新增的 `stack_height_before`。原始输入对象和原始 JSON 文件保持不变。输入和输出
路径相同时命令直接拒绝执行。

独立 WCS 输出继续使用原接口字段：

- `seq` 按新的执行顺序全局连续编号 `1..N`。
- `layer_id` 仍按最终 `position.z` 分组，只表达几何高度层。
- `stack_height_before` 只写入 `_execution.json` 的 `packed_items[]`；WCS
  `layers[].cartons[]` 和对应 map 的 `packed_items[]` 均不包含该字段。
- `box_unique_id` 必须和同批生成的 `_map.json` 一起留存，不能只发送 case 数组后
  丢弃映射。
- 传送带和机械臂必须以全局 `seq` 为执行依据，不能依赖 `layers` 数组嵌套顺序。

CLI 会先把 execution、map、cases 全部写入同目录临时文件并回读校验，再执行原子
替换。WCS cases 最后发布，作为本批文件已经配套完成的发布标志。现场文件监听器
只能在 cases 文件变更后读取同名 map，不能单独监听 map 文件启动任务。替换前的
旧文件会保留为临时备份；任一替换失败时，整套 execution/map/cases 按逆序回滚，
避免旧 cases 与新 map 错配。

## 后续改进记录

- `tolerances.xy_tolerance` 尚未统一注入主装箱、GCP、重排和全部救援路径。当前多条
  路径仍直接使用 `2.0`，少数救援调用使用 `0.0`。后续应由配置加载器统一读取并
  逐层传递，同时增加不同容差配置下的坐标间隙和最终门禁回归测试。
- `force_publish_on_gate_failure` 是现场联调阶段的临时策略。后续应根据真实末端执行器
  外廓和控制器轨迹重新标定垂直下降、预放、推进、局部抬升及退出走廊，并记录每条
  依赖的阶段和实际交叠量；误判消除后应关闭强制发布，恢复完整门禁作为发布条件。

## 失败策略

`force_publish_on_gate_failure: false` 时，以下任一情况都不会生成执行文件：

- 非底层箱找不到直接支撑。
- 箱子 ID 缺失或重复。
- 位置、尺寸或吸盘矩形缺失/非法。
- 坐标、尺寸、吸盘矩形或托盘尺寸包含 NaN/Infinity，或者实物箱体越过托盘边界。
- 安全包络产生循环依赖，即不存在只靠换序即可完成的垂直下降和斜向推进顺序。
- 在配置时间内找不到满足最大占用方向数的执行顺序。
- 排序后的逐箱回放发现支撑或扫掠路径不成立。

`force_publish_on_gate_failure: true` 时，规划器先完整执行上述门禁。若失败，则按托盘
重新建立只包含直接支撑和高度感知局部走廊的依赖图，以同一空间阶梯波生成强制
顺序，并继续发布 execution、WCS cases 和 WCS map。三份文件从同一份 execution
报告派生，不会为 WCS 再规划一次。

以下基础错误即使启用强制发布也会拒绝：箱子 ID 缺失或重复、坐标或尺寸非法、箱子
越过托盘边界、非底层箱没有直接支撑、支撑拓扑成环，以及强制顺序本身无法满足
保留的支撑/局部走廊依赖。强制发布绕过的路径门禁原本用于近似机械臂包络，因此
控制器仍必须执行自身路径规划和碰撞检查。控制台出现 `forced execution order` warning
时，表示该托盘没有通过离线路径门禁。

## 现场参数设置与故障调整

现场参数应按“先验证顺序，再测量误差，最后加入安全余量”的方式设置。不要在一次
测试中同时大幅调整多个参数，否则无法判断具体是哪种下降路径导致冲突。

### 推荐配置档位

| 场景 | `coordinate_tolerance_mm` | `box_xy_clearance_mm` | `suction_xy_clearance_mm` | `suction_z_clearance_mm` | `require_suction_pose` |
|---|---:|---:|---:|---:|---|
| 接口和顺序验证 | `0.000001` | `0` | `0` | `0` | `true` |
| 空箱低速初测 | `0.000001` | `1` | `2` | `2` | `true` |
| 按现场测量值运行 | `0.000001` | 按箱体 XY 误差计算 | 按吸盘/腕部外廓计算 | 按 Z 误差计算 | `true` |

“空箱低速初测”档位只是在没有测量数据时用于发现干涉的起始值，不应直接作为正式
生产参数。正式参数必须根据机械臂、吸盘、箱体和视觉/定位系统的实测最大误差确定。

定向推进参数必须和机器人控制器的实际路径一致：

| 场景 | `approach_offset_x_mm` | `approach_offset_y_mm` | `approach_z_clearance_mm` | `approach_box_xy_clearance_mm` | `approach_suction_xy_clearance_mm` |
|---|---:|---:|---:|---:|---:|
| 当前交付配置 | `20` | `20` | `20` | `0` | `0` |
| 现场低速初测 | 实测 X 推进分量 | 实测 Y 推进分量 | 实测预放高度差 | `0` 起逐步增加 | `2` 起逐步增加 |
| 按现场测量值运行 | 实测 X 推进分量 | 实测 Y 推进分量 | 实测预放高度差 | 箱体推进误差上界 | 吸盘/腕部推进误差上界 |

不要用增大安全余量代替错误的推进位移。应先测量预放点到目标点的 X/Y/Z 差值，
再分别设置 offset 和 clearance。历史诊断中，668 箱样例在旧偏移和安全余量组合下
曾形成依赖环；当前参数已调整为 `20/20/20/0` 并可完成规划。该结果只证明离线模型
可排出顺序，正式现场值仍应以机械臂实测轨迹为准。

### 按现场问题调整

| 现场现象 | 调整方案 |
|---|---|
| 箱体下降时擦碰旁边箱子 | 每次将 `box_xy_clearance_mm` 增加 `1～2 mm`，重新生成方案后测试。 |
| 箱体不碰，但吸盘、法兰、腕部或管路碰箱 | 每次将 `suction_xy_clearance_mm` 增加 `1～2 mm`。 |
| 吸盘接近目标箱顶时碰到旁边较高箱子 | 每次将 `suction_z_clearance_mm` 增加 `1～2 mm`。 |
| 实际推进方向或距离与规划模型不同 | 先停机测量预放点到目标点的 X/Y 分量，修正 `approach_offset_x_mm` 和 `approach_offset_y_mm`。 |
| 箱体在斜向推进或最终下降时擦碰 | 每次将 `approach_box_xy_clearance_mm` 增加 `1～2 mm`。 |
| 吸盘、法兰或腕部在斜向推进时擦碰 | 每次将 `approach_suction_xy_clearance_mm` 增加 `1～2 mm`。 |
| 机器人先在高处推进再下降 | 将实测推进平面与目标放置高度的差写入 `approach_z_clearance_mm`。 |
| 机械臂实际 XY 落点存在固定偏差 | 先标定机械臂，再把标定后的最大残余误差计入箱体和吸盘 XY 余量。 |
| 算法提示箱子悬空，但确认只是坐标小数误差 | 检查坐标输出精度，只将 `coordinate_tolerance_mm` 提高到 `0.001` 或 `0.01`。 |
| 提示缺少 `suction_rect_*` | 修复吸盘字段生成，不建议将 `require_suction_pose` 改为 `false`。 |
| 增加余量后提示依赖环或不生成 execution 文件 | 当前垛型无法在该余量下仅靠换序执行；只能使用真实测量允许的余量，或重新规划箱子位置。 |

### 现场测量后的计算方法

```text
box_xy_clearance_mm
= 箱体最大水平摆动或偏移 + 预留安全量

suction_xy_clearance_mm
= 最大 XY 定位误差
  + 吸盘、法兰或腕部超出 suction_rect 的距离
  + 预留安全量

suction_z_clearance_mm
= 最大 Z 定位误差
  + 吸盘压缩量或箱体变形量
  + 预留安全量

approach_offset_x_mm / approach_offset_y_mm
= 预放点到目标点的实测水平位移分量

approach_box_xy_clearance_mm
= 推进阶段箱体最大水平摆动或定位误差 + 预留安全量

approach_suction_xy_clearance_mm
= 推进阶段末端外廓误差 + 预留安全量
```

在没有企业安全规范给出其它要求时，预留安全量可以先取 `1～2 mm`，再根据空箱
低速测试结果调整。所有 XY 余量均表示“每侧扩大”：例如配置为 `5`，检查区域的
总长度和总宽度各增加 `10 mm`。

### 参数安全限制

- `coordinate_tolerance_mm` 只用于几何计算精度，不能用于补偿机械臂误差。正常应
  保持 `0.000001`，不建议超过 `0.1 mm`。数值过大可能把悬空、越界或微小重叠
  误判为合法。
- 现场机械臂执行应保持 `require_suction_pose: true`。设置为 `false` 只适用于没有
  吸盘数据的离线分析，因为缺失吸盘矩形的箱子将跳过吸盘下降路径检查。
- 安全余量增大后出现依赖环是有效的安全结果，表示现有坐标布局不可执行。不得为了
  生成 execution 文件而把参数降到低于现场实测误差的水平。
- `approach_offset_x_mm`、`approach_offset_y_mm` 和 `approach_z_clearance_mm` 必须
  描述机器人控制器实际使用的预放路径；路径模型不一致时，规划通过也不能证明现场
  无碰撞。
- 每次调整配置后都要重新执行 `run_packing.py`，并使用同一时间戳新生成的
  `_execution.json`、`_execution_wcs.json` 和 `_execution_wcs_map.json`，不能混用
  不同批次文件。

## 现场测试建议

1. 先写入实测 `approach_offset_x/y_mm` 和 `approach_z_clearance_mm`；仅将
   `box_xy_clearance_mm`、`suction_xy_clearance_mm`、`suction_z_clearance_mm`、
   `approach_box_xy_clearance_mm` 和 `approach_suction_xy_clearance_mm` 设为低速测试
   起始值，验证 WCS `seq`、传送带顺序和机械臂目标箱映射。
2. 用空箱或替代箱测量实际预放点、推进 X/Y/Z 分量、定位误差和腕部/吸盘外廓。
3. 将测得的上界写入 `execution_sequence` 配置段后重新运行 `run_packing.py`。
4. 从混高托盘开始低速执行，记录每步目标坐标、实际坐标、报警和人工干预。
5. 任何碰撞、擦碰、压箱或顺序不一致都应停止该托盘测试，不允许现场临时跳序。
