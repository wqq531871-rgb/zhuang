# 独立执行顺序规划

该功能位于 `src/execution/`，在装箱算法完成最终坐标规划之后运行。它不调用或修改
GCP、beam、配方、救援链等装箱逻辑，也不改变原始 `packing_plan_*.json`。

## 目标

- 固定每个托盘的最终箱子集合、相对布局、尺寸和朝向；在托盘剩余空间内整体居中垛型。
- 保证直接支撑箱先放置。
- 用名义路径模型评估箱体和已保存吸盘姿态的预放下降、斜向推进、最终下降及抬升风险。
- 所有托盘使用同一套有向空间阶梯波，从远端原点向机器人侧确定性扩散。
- 输出保留原装箱报告的业务字段，并更新执行顺序、绝对 XY 坐标和执行高度字段。

## 机械臂运动模型

现场机械臂位于托盘 `x_max_y_max` 一侧。目标箱最终位置为 `P=(x,y,z)`，预放位置为：

```text
P_pre = (x + approach_offset_x_mm,
         y + approach_offset_y_mm,
         z + approach_z_clearance_mm)
```

每次放箱按以下四段名义路径检查：

1. 箱体和吸盘在 `P_pre` 上方垂直下降。
2. 箱体和吸盘从 `P_pre` 沿 `-X/-Y` 斜向推进到目标 XY。
3. 箱体在目标位置完成最终下降并落到直接支撑面。
4. 放箱后吸盘在目标位置垂直抬升。

当前 X/Y 偏移均为 `20 mm`，斜向距离约为 `28.3 mm`。该模型验证箱体和吸盘的
轴对齐外廓，不替代机器人控制器的 IK、关节限位、完整连杆碰撞和速度规划。

### 单向性不变量

吸盘矩形锚定在箱子的 `suction_box_corner` 角并向接近侧悬出。`origin: x_min_y_min`
时该角为箱子的 `(x_min, y_min)`，吸盘向 `+X/+Y` 悬出（现场 668 箱样例中吸盘为
600×800 mm，箱子为 350×530 mm，悬出量分别为 250 mm 和 270 mm）。预放偏移、斜向
推进和吸盘悬出因此全部只落在 `+X/+Y` 一侧：

```text
扫掠包络 = [x, x_max + approach_offset_x_mm] × [y, y_max + approach_offset_y_mm]
```

由此得到执行顺序必须满足的单向性不变量：

- 放箱瞬间 **`x+` 和 `y+` 两侧必须空闲**（`origin` 决定这两个方向，见下表）。
- `x-` 和 `y-` 两侧可以被完全放满，因为箱体和吸盘都不会经过那里。

| `origin` | 机械臂一侧 | 必须空闲的方向 | 可以放满的方向 |
|---|---|---|---|
| `x_min_y_min` | `x_max_y_max` | `x+`、`y+` | `x-`、`y-` |
| `x_min_y_max` | `x_max_y_min` | `x+`、`y-` | `x-`、`y+` |
| `x_max_y_min` | `x_min_y_max` | `x-`、`y+` | `x+`、`y-` |
| `x_max_y_max` | `x_min_y_min` | `x-`、`y-` | `x+`、`y+` |

`pocket_rule: approach_directional`（默认）按该表判定“凹坑”，与
`approach_offset_*` 的具体数值无关，只依赖偏移为正，因此在轨迹参数标定完成前也
可以作为硬门禁使用。`pocket_rule: open_corner` 保留旧的无方向规则，只按
`max_occupied_directions` 限制被占方向总数；该规则会放行 `{x-, y+}`、`{x+, y-}`
这类对本机械臂实际构成凹坑的组合，仅用于离线验证或其它机器人站位。

## 依赖与排序规则

每个托盘先建立有向依赖图：

1. 直接支撑箱指向上层箱；接触面积按 `original_*`/`raw_*` 实物尺寸判断，
   不把算法用于留间隙的膨胀占位尺寸当作真实支撑。
2. 对支撑层级更高的箱 U，如果待放低层箱 L 进入 U 的实物箱体局部前沿，则增加
   `L -> U`。水平间隙小于等于 `side_neighbor_clearance_mm` 时也建立依赖，不受吸盘
   矩形或斜向推进参数影响。这只延迟局部相邻的上层箱，不要求整层完成。
   `pocket_rule: approach_directional` 时该判定只在接近侧生效：U 完全位于 L 的
   `x-` 或 `y-` 一侧（即 `U.x_max <= L.x_min` 或 `U.y_max <= L.y_min`）时不建边，
   因为扫掠包络不会到达那里。无方向版本会在退出侧生成与单向约束反向的边，
   在混高托盘上可以和真实接近路径形成依赖环。
3. 根据 `origin` 识别远端 X/Y 托盘边。远端边界箱存在向内侧邻箱时，优先保留
   `边界目标箱 -> 内侧邻箱`，防止边界和内侧箱形成夹持。该依赖高于普通波前；与
   支撑、局部低层完成或凹坑硬约束冲突时允许放弃，并写入托盘诊断。
   `approach_directional` 的凹坑门禁已经覆盖全部箱子的同类约束，该规则退化为
   远端边界箱的排序偏好；放弃某条边不会再产生凹坑放置。
4. `path_gate_mode: score_only` 时，箱体/吸盘下降、预放下降、斜向推进和最终下降
   不生成拓扑边，只在核心顺序完成后逐箱重放并记录软风险。
5. `path_gate_mode: hard` 时，上述路径模型恢复为严格依赖和最终门禁，用于轨迹参数
   已完成现场标定后的验证。
6. 使用 Kahn 排序确认核心依赖图无环，再按有向空间阶梯波建立稳定的正向偏好。
   远端目标箱的空间优先级沿依赖图反向传播给其前置链；每一步都从尚未放置箱子的
   偏好头开始扫描，只选择硬依赖已满足、当前凹坑判定通过且选择后剩余箱仍可完成
   的第一个箱子。这样会先完成解锁远端目标所需的前置链，再立即放置该目标，
   不会在等待期间先放无关的近端箱。
7. 剩余可完成性检查固定已经放置的前缀，从剩余集合反向剥离。候选必须是剩余 DAG
   的 sink，并且相对固定前缀和其它剩余箱通过凹坑判定：
   `approach_directional` 要求接近侧两个方向都没有顶面高于候选箱底面的邻箱；
   `open_corner` 沿用“最多两条相邻边、禁止相对两边和三/四边”的旧判据。
8. 最终结果逐箱回放支撑、局部低层完成和凹坑硬约束。`score_only` 模式另外
   计算垂直下降和三段接近路径的风险清单，但风险不会改变 `seq`、触发回退或阻止
   execution/WCS 文件发布。凹坑判定按 `side_neighbor_clearance_mm` 的水平间隙和
   “邻箱顶面高于候选箱底面”判断，比 20 mm 名义偏移更保守，因此不依赖轨迹标定。

有向空间阶梯波分别按 X/Y 进度聚类得到 `x_rank`、`y_rank`，再计算：

```text
spatial_ring = max(x_rank, y_rank)
wave = spatial_ring + 2 * support_tier
排序键 = (wave, support_tier, spatial_ring, x_rank, y_rank, stable_index)
```

第一物理层的 `support_tier=0`，因此从 `x_min_y_min` 空间环严格向外扩散。上层箱按
`2 * support_tier` 计入波次，等价于**每升高一个支撑层，要等地面前沿再向外推进两个
空间环**；同一波次内 `support_tier` 升序优先，所以低层箱始终先于同波次的上层箱。
两条规则合起来形成“地面先铺开、垛型随后逐步升高”的金字塔形。所有托盘无条件使用
这一套排序，不再进行逐层/阶梯模式分类。

以现场 4x4 柱 x 2 层的托盘 1 为例（地面箱高 480、上层箱高 240）：原点柱的上层箱
`wave = 0 + 2 = 2`，与 ring 2 的地面箱同波次但 `support_tier` 更大，因此排在 9 个
ring 0~2 地面箱之后、7 个 ring 3 地面箱之前。权重取 `1` 时它会排到 ring 1 地面箱
之前（第 2 箱），取 `2` 之后落到第 10 箱。

空间波是满足支撑、局部低层完成、远端边界夹持和凹坑约束后的主排序。只有这些
核心规则需要时才允许最小局部偏离；下降和斜向推进风险排在最后，只评分和记录。
规划器会在 warning 中记录核心排序偏离的箱号与原因，不回退旧逐层顺序。

`approach_directional` 下空间波和凹坑判定方向一致：同一支撑层内，`+X/+Y` 邻箱的
`x_rank`/`y_rank` 一定不小于目标箱，因此排序键本身就把它们排在后面，凹坑门禁只在
跨支撑层、边界夹持或局部低层完成造成冲突时才产生偏离。

“低层优先”只是偏好，不是硬规则。混高托盘上如果先放地面邻箱会把某个上层箱永久
封进凹坑，残余可完成性检查会在选中该地面箱之前就否掉它，规划器改先放上层箱并记录
一条 `open_direction` + `lookahead=true` 偏离。现场 668 箱样例中托盘 10、11 就是这种
情况：它们的第 2 箱仍然是上层箱，因为地面邻箱比该上层箱的底面更高。

## 支持的原点

- `x_min_y_min`（默认）
- `x_min_y_max`
- `x_max_y_min`
- `x_max_y_max`

坐标语义与算法报告一致：原点位于托盘底面，x 为长方向，y 为宽方向。
现场机械臂位于 `x_max_y_max` 一侧时应保持 `origin: x_min_y_min`，使波源位于远端。
其它原点只用于不同机器人站位或离线验证，修改前必须同时确认实际推进方向。

## 垛型居中和当前最高高度

执行顺序确定后，规划器按所有箱子在托盘底面的实物 XY 投影包络计算整体平移量：

```text
shift_x = (右侧余量 - 左侧余量) / 2
shift_y = (上侧余量 - 下侧余量) / 2
```

原垛型从 `x_min_y_min` 开始时，上式等价于把远端剩余空间分别除以 2。某一轴的
垛型投影已经占满托盘、该轴总剩余空间不大于几何容差时，该轴平移量固定为 `0`。
平移同时更新 `position.x/y` 和四个绝对 `suction_rect_*` 坐标，`position.z`、箱子
相对位置、尺寸和朝向不变。依赖绝对 XY 的 `robot_depth` 和 `robot_depth_band` 也按
原 `robot_reference` 重新计算。平移后重新执行边界、支撑、局部低层完成和凹坑
硬门禁；`score_only` 模式只记录垂直下降、定向推进和最终下降风险，`hard` 模式才把
这些路径检查作为发布门禁。

规划器再按最终 `seq` 顺序给每个箱子增加 `stack_height_before`：

```text
stack_height_before(i)
= max(position.z + 实物箱高)，范围为 seq < i 的所有已放箱
```

第一箱的值固定为 `0.0`。该字段表示放置当前箱之前的垛型最高顶面，单位与现有
坐标一致为毫米，不包含机械臂额外安全余量。

## 配置

是否启用该功能以及规划参数统一从 `config/packing_config.yaml` 的
`execution_sequence` 段读取：

```yaml
execution_sequence:
  enabled: true
  path_gate_mode: score_only
  origin: x_min_y_min
  coordinate_tolerance_mm: 0.000001
  box_xy_clearance_mm: 0.0
  suction_xy_clearance_mm: 0.0
  suction_z_clearance_mm: 0.0
  approach_offset_x_mm: 20.0
  approach_offset_y_mm: 20.0
  approach_z_clearance_mm: 20.0
  approach_box_xy_clearance_mm: 0.0
  approach_suction_xy_clearance_mm: 0.0
  require_suction_pose: true
  pocket_rule: approach_directional
  max_occupied_directions: 2
  side_neighbor_clearance_mm: 5.0
  side_height_tolerance_mm: 2.0
  preserve_open_direction: true
  force_publish_on_gate_failure: true
  max_sequence_search_seconds_per_pallet: 1.0
  forced_sequence_search_seconds_per_pallet: 30.0
  scan_column_tolerance_mm: 5.0
```

- `enabled: true` 时，`run_packing.py` 在原装箱报告保存后自动生成 execution、
  WCS cases 和 WCS map。
- `enabled: false` 时只生成原装箱报告和托盘汇总 Excel。
- `path_gate_mode: score_only`（现场默认）时，下降和斜向推进只生成风险诊断；设为
  `hard` 时恢复原严格路径门禁。路径参数未完成现场标定前不要使用 `hard`。
- `pocket_rule: approach_directional`（现场默认）按 `origin` 推导的接近方向判定凹坑；
  设为 `open_corner` 时退回旧的无方向判据，只用于离线验证或其它机器人站位。
- 独立命令的输入和输出路径属于单次任务参数，继续通过命令行指定，不写入公共配置。
- 原点和数值参数默认使用配置文件；独立命令的显式参数仅覆盖本次运行。
- `--xy-clearance-mm` 会同时覆盖箱体和吸盘 XY 余量；也可分别使用
  `--box-xy-clearance-mm`、`--suction-xy-clearance-mm`。
- `--allow-missing-suction` 和 `--require-suction-pose` 可临时覆盖
  `require_suction_pose`。

### 参数解释

#### `coordinate_tolerance_mm`

几何计算容差，用于判断箱子是否位于托盘底面、上下箱顶面和底面是否接触、两个
矩形是否存在有效重叠，以及箱子是否越过托盘边界。默认值 `0.000001 mm` 只用于
吸收浮点计算误差，不是机械臂定位误差。通常应保持默认值；把它设置成数毫米可能
导致悬空、微小越界或微小重叠被误判为合法。

#### `box_xy_clearance_mm`

箱体垂直下降路径的 XY 安全包络。风险评估会把目标箱的实物矩形向 X/Y 四周分别
扩大该数值，再检查已经放置的箱子是否进入下降通道。例如设置为 `10`，表示箱体
每一侧增加 10 mm，检查矩形的总长度和总宽度各增加 20 mm。该值可覆盖箱体摆动、
抓取偏移和部分机械臂误差；值越大，记录的风险通常越多。在 `hard` 模式下，值越大
也越容易产生无法换序解决的依赖环。
`0` 仅表示当前布局不增加箱体包络；若现场需要 2 mm 间隙，必须由上游布局产生至少
对应的物理间隙，不能靠调整执行顺序绕过。

#### `suction_xy_clearance_mm`

吸盘垂直下降路径的 XY 安全包络。风险评估以箱子保存的
`suction_rect_x_min/x_max/y_min/y_max` 为基础，向四周分别扩大该数值。它主要用于
覆盖吸盘边缘、法兰、管路、腕部外廓和 XY 定位误差。设置为 `10` 同样表示吸盘
矩形每一侧增加 10 mm。它与 `box_xy_clearance_mm` 分开配置，因为箱体外廓和机械臂
末端执行器外廓通常不同。

#### `suction_z_clearance_mm`

吸盘下降到目标箱顶面附近时要求保留的高度余量。假设目标箱顶面为 500 mm，配置
为 `20`，则吸盘 XY 扫掠区域内已经放置的其它箱子顶面必须不高于约 480 mm；高于
该高度会被视为遮挡。该值用于覆盖 Z 定位误差、吸盘压缩量和末端执行器低于理论
姿态的外廓。值越大，允许靠近目标箱的已放高箱越少。

#### `require_suction_pose`

是否强制要求每个箱子具有完整、有限且有效的四个 `suction_rect_*` 字段。设置为
`true` 时，任一箱子缺少吸盘矩形都会拒绝生成该执行方案。设置为 `false` 时，缺少
吸盘字段的箱子仍检查直接支撑，并跳过该箱子的吸盘下降路径风险评估或硬门禁。
现场机械臂方案建议保持 `true`。

### 定向推进参数

- `approach_offset_x_mm` / `approach_offset_y_mm`：目标位置到预放位置的 X/Y 水平
  分量。当前交付值均为 `20 mm`，表示机械臂从目标的 `+X/+Y` 一侧开始约 `28.3 mm` 的
  斜向推进。应按现场实际推进位移标定；它们描述路径长度，不是安全余量。
- `approach_z_clearance_mm`：预放位置相对目标底面的额外 Z 抬高量。当前交付值为
  `20 mm`。若现场先在更高处推进再最终下降，应填写实测高度，规划器会据此扩大
  推进和最终下降的 Z 扫掠区间。
- `approach_box_xy_clearance_mm`：箱体在预放下降、斜向推进和最终下降阶段每侧增加的
  XY 安全包络。默认 `0`，现场出现箱体推进擦碰时按实测摆动误差逐步增加。
- `approach_suction_xy_clearance_mm`：吸盘在预放下降和斜向推进阶段每侧增加的 XY
  安全包络。当前交付值为 `0`；现场完成吸盘边缘、腕部外廓和推进阶段误差测量后，
  再按实测上界增加。

推进扫掠使用移动矩形与静态矩形的精确斜向相交测试，不用起终点外接矩形代替，
避免把斜线路径两侧实际不会经过的区域误判为阻挡。

### 防凹坑参数

- `pocket_rule`：凹坑判定规则，现场应保持 `approach_directional`。该规则要求接近侧
  两个方向（`origin: x_min_y_min` 时为 `x+`、`y+`）在放箱瞬间没有邻箱，退出侧
  （`x-`、`y-`）允许放满。`open_corner` 是旧的无方向规则，只按
  `max_occupied_directions` 限制被占方向总数。
- `max_occupied_directions`：仅 `pocket_rule: open_corner` 时生效。允许同高或更高邻箱
  占用的最大方向数，两条边还必须相邻并形成一个角；`x-/x+`、`y-/y+`、任意三边和
  四边包围始终禁止。`approach_directional` 下该值不参与判定。
- `side_neighbor_clearance_mm`：判定侧面邻箱以及局部抬升/退出走廊时允许的最大水平
  间隙，间隙小于等于该值时纳入依赖。局部低层前沿使用实物箱体投影判断，吸盘
  矩形只用于定向退出扫掠，因此吸盘内缩不会放过紧邻箱体。
- `side_height_tolerance_mm`：比较邻箱和目标箱顶面高度时使用的容差。明显低于目标
  箱顶面的邻箱不计入硬包围方向。
- `preserve_open_direction`：是否启用凹坑硬门禁。现场执行应保持 `true`；设为
  `false` 时只关闭该门禁，支撑、局部低层完成、边界夹持选择和有向空间波仍执行。
- `force_publish_on_gate_failure`：核心规划失败时是否继续生成执行三件套。`score_only`
  已不会因下降或斜向推进模型失败，因此该开关只处理核心依赖、凹坑或超时失败。
- `max_sequence_search_seconds_per_pallet`：每个托盘完整路径规划的时间预算，覆盖邻接
  预计算、正向选择和残余反向剥离。
- `forced_sequence_search_seconds_per_pallet`：完整规划失败后，强制安全排序的独立时间
  预算。当前值为 `30` 秒；超时会停止该托盘发布并报告错误，不会关闭支撑、局部
  走廊或凹坑规则。
- `scan_column_tolerance_mm`：X/Y 进度的锚点聚类容差。相对执行原点的坐标前沿差不
  超过该值时视为同一级；聚类以锚点为基准，不做链式扩张。该参数只决定空间环的
  排序偏好，不替代 `coordinate_tolerance_mm` 的几何判断。

有向空间波使用 `(wave, support_tier, spatial_ring, x_rank, y_rank, stable_index)` 作为
正向键，其中 `wave = spatial_ring + 2 * support_tier`。坐标等级相同的箱子保持输入
顺序，不再用未聚类的精确坐标打破平局。支撑层权重 `2` 是代码常量
`_TIER_WAVE_RINGS`，不作为配置项开放；改动它会同时改变全部托盘的垛型建造轮廓，
必须重新跑 11 托盘风险回归。

支撑、局部低层完成、远端边界夹持和凹坑判定决定核心顺序，必要时可产生最小局部
扫描偏离。箱体/吸盘下降和斜向推进在 `score_only` 模式不产生扫描偏离。
一次调度成功后至多输出一条偏离 warning，包含去重后的总数和最多 8 项预览；每项
标明 `expected`、`selected` 以及 `hard_dependency` 或 `open_direction`，因残余不可
完成而跳过局部合法候选时还会标明 `lookahead=true`。规划器不再输出逐层/阶梯模式
分类日志。

## 一条命令生成全部方案

正常运行时只需要执行：

```powershell
python code/run_packing.py --config code/config/packing_config.yaml
```

同一时间戳下始终生成：

- `packing_plan_<timestamp>.json`：原始装箱方案，箱子顺序保持算法输出顺序。
- `packing_plan_summary_<timestamp>.xlsx`：原方案的托盘统计表。

当 `execution_sequence.enabled: true` 时，还会自动生成：

- `packing_plan_<timestamp>_execution.json`：机械臂最终执行方案；垛型按轴居中，
  `packed_items` 使用最终顺序，每箱包含 `stack_height_before`。
- `packing_plan_<timestamp>_execution_wcs.json`：WCS 接口 2 的 case 数组，`seq` 使用
  新执行顺序，不包含 `stack_height_before`。
- `packing_plan_<timestamp>_execution_wcs_map.json`：机器人侧留存映射，保存
  `box_unique_id -> 执行托盘坐标与顺序`，不包含 `stack_height_before`。

当 `execution_sequence.enabled: false` 时，不生成以上三个 execution 文件。

### 输出接口使用哪个文件

调用 WCS 的“规划订单输出”接口
`/adaptor/api/wcs/sendpalletplanresult` 时，应把
`packing_plan_<timestamp>_execution_wcs.json` 的完整 JSON 数组作为请求体发送。

- 不要把原始 `packing_plan_<timestamp>.json` 发给该接口，它不是接口 2 的字段结构。
- 不要把 `_execution.json` 直接发给 WCS；它是机器人侧完整坐标方案。
- 不要把 `_execution_wcs_map.json` 发给 WCS；该文件必须留在机器人侧，供接口 3/4
  根据 `box_unique_id + seq` 查找目标坐标和吸盘姿态。

## 独立重跑命令

已经存在原装箱 JSON，需要单独重新生成执行顺序时，仍可使用：

```powershell
python code/run_execution_planning.py `
  output/packing_plan_20260712_092845.json `
  --output output/packing_plan_20260712_092845_execution.json `
  --config code/config/packing_config.yaml `
  --origin x_min_y_min
```

同时输出 WCS case 数组：

```powershell
python code/run_execution_planning.py `
  output/packing_plan_20260712_092845.json `
  --output output/packing_plan_20260712_092845_execution.json `
  --wcs-output output/packing_plan_20260712_092845_execution_wcs.json
```

只要指定 `--wcs-output`，CLI 还会自动输出
`packing_plan_20260712_092845_execution_wcs_map.json`。该 sidecar 保存
`box_unique_id -> 执行托盘坐标与顺序`，机器人服务用 `seq-1` 定位到按执行顺序排列的
`packed_items`，取得箱子 ID、目标坐标和 `suction_*` 字段。可用
`--wcs-map-output` 指定其它路径。该文件不包含仅供装箱结果留存的
`stack_height_before`。

加入现场测得的安全包络：

```powershell
python code/run_execution_planning.py INPUT.json `
  --xy-clearance-mm 10 `
  --z-clearance-mm 5
```

- `--xy-clearance-mm` 同时扩大箱体和吸盘 XY 扫掠矩形。
- `--z-clearance-mm` 要求吸盘下降到箱顶时与已放箱顶保留对应高度余量。
- 所有容差必须是有限且非负的数字；`NaN`、`Infinity` 和负数直接拒绝。
- 默认要求每箱已有完整 `suction_rect_*` 字段。
- `--allow-missing-suction` 仅供不启用吸盘约束的数据使用，现场机械臂方案不建议开启。

## 输出保证

执行报告保留原报告的根字段、托盘业务字段、箱子集合、尺寸、朝向和相对布局。
允许变化的执行字段包括 `packed_items` 数组顺序、`seq`、`position.x/y`、四个
`suction_rect_*` 绝对 XY 坐标、重新计算的 `robot_depth`/`robot_depth_band`，以及
新增的 `stack_height_before` 和托盘级 `execution_sequence_diagnostics`。诊断包含
路径模式、软路径风险、未保留边界夹持依赖和凹坑违规清单。原始输入对象和原始 JSON
文件保持不变。输入和输出
路径相同时命令直接拒绝执行。

诊断计算不属于发布门禁。某一诊断阶段异常时，该阶段的计数和清单保持为空，并增加
对应的 `*_evaluation_error` 字段；已经完成的核心顺序仍继续生成 execution 和 WCS。

独立 WCS 输出继续使用原接口字段：

- `seq` 按新的执行顺序全局连续编号 `1..N`。
- `layer_id` 仍按最终 `position.z` 分组，只表达几何高度层。
- `stack_height_before` 只写入 `_execution.json` 的 `packed_items[]`；WCS
  `layers[].cartons[]` 和对应 map 的 `packed_items[]` 均不包含该字段。
- `execution_sequence_diagnostics` 只写入 `_execution.json` 的托盘对象；WCS cases 和
  WCS map 均不包含该字段。
- `box_unique_id` 必须和同批生成的 `_map.json` 一起留存，不能只发送 case 数组后
  丢弃映射。
- 传送带和机械臂必须以全局 `seq` 为执行依据，不能依赖 `layers` 数组嵌套顺序。

CLI 会先把 execution、map、cases 全部写入同目录临时文件并回读校验，再执行原子
替换。WCS cases 最后发布，作为本批文件已经配套完成的发布标志。现场文件监听器
只能在 cases 文件变更后读取同名 map，不能单独监听 map 文件启动任务。替换前的
旧文件会保留为临时备份；任一替换失败时，整套 execution/map/cases 按逆序回滚，
避免旧 cases 与新 map 错配。

## 变更记录

### 2026-07-25 支撑层加权，地面先铺开

现象：`ui_packing_plan_20260725_163659_execution.json` 中每个托盘的**第 2 箱都是上层
箱**。托盘 1 的第 2 箱是 `1`（原点柱顶，z=480），而第 3、4、5 箱（`154`、`151`、`155`）
才是 ring 1 的地面箱。垛型在只放了 1 个箱子时就升到满高，现场不合理。

根因：旧正向键为 `(wave, spatial_ring, x_rank, y_rank, support_tier, stable_index)`，
而 `wave = spatial_ring + support_tier`。同一波次内 `spatial_ring = wave - support_tier`
是常数减 tier，因此 **`spatial_ring` 升序等价于 `support_tier` 降序**；键里
`spatial_ring` 排在 `support_tier` 前面，同波次里层级高的箱子永远抢先。这不是几何
判定错误，也没有产生风险，纯粹是排序键分量次序造成的建造轮廓问题。

修改：`wave` 改为 `spatial_ring + 2 * support_tier`，排序键改为
`(wave, support_tier, spatial_ring, x_rank, y_rank, stable_index)`。依赖图、凹坑门禁和
残余可完成性检查全部未改动——正向键只决定“先试谁”，绕不过任何硬约束。

验证（668 箱 / 11 托盘，其余参数不变）：

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| `soft_path_risk_count` | 0 | 0 |
| `pocket_violation_count` | 0 | 0 |
| `boundary_clamp_relaxed_count` | 0 | 0 |
| 平均 `stack_height_before` | 682 mm | 602 mm |
| 地面层未铺满就上层的箱数 | 318 | 138 |
| `approach_suction_xy_clearance_mm=2` 时的风险数 | 161 | 45 |
| 最慢托盘规划耗时 | 0.171 s | 0.234 s |

托盘 1 前 6 箱由 `150, 1, 154, 151, 155, 5` 变为 `150, 154, 151, 155, 158, 159`，原点柱
顶箱从第 2 箱推迟到第 10 箱。11 个托盘全部保持 `GEOMETRICALLY_FEASIBLE`，箱子集合和
坐标布局不变，`path_gate_mode: hard` 下同样 0 风险 0 失败。地面先铺开还顺带把吸盘
推进余量的敏感度降低了约 72%，因为下降时周边高箱更少。

### 2026-07-25 凹坑判定改为有向

现象：`ui_packing_plan_20260725_122420_execution.json` 中托盘 11 的第 9 箱（644）和
第 13 箱（635）被放入凹坑，托盘 11 记录 18 条、托盘 5 记录 12 条
`box pre-position descent` 软风险，而 `pocket_violation_count` 为 `0`。

根因有两条，都在执行顺序规划内部，与装箱布局无关：

1. 旧凹坑判据 `max_occupied_directions=2` + 禁止相对边是无方向的，会放行
   `{x-, y+}`（644 的情形）和 `{x+, y-}`（635 的情形）。这两种组合对
   `origin: x_min_y_min` 的机械臂就是凹坑。
2. 局部退出走廊判定是四向对称的，会生成与真实单向接近路径反向的边。托盘 11 因此
   出现 `169 -> 647 -> 62 -> 169` 等 4 个依赖环（其中 `62 -> 169` 是伪约束，169 在
   62 的 `x-` 侧），`path_gate_mode: hard` 直接报环，项目只能停在 `score_only`，
   真实路径模型完全不参与排序；`_far_boundary_clamp_dependencies` 也因此放弃了
   4 条安全边（644→647、635→82、645→648、646→649），与 4 条软风险一一对应。

修改：新增 `pocket_rule`，默认 `approach_directional`，按 `origin` 推导接近方向并
要求这两个方向空闲；局部退出走廊判定同步限制到接近侧半空间。旧行为保留为
`pocket_rule: open_corner`。

验证（668 箱 / 11 托盘）：`soft_path_risk_count` 由 `12 + 18` 降到全部 `0`，
`pocket_violation_count` 与 `boundary_clamp_relaxed_count` 均为 `0`，依赖环 `0`，
11 个托盘全部保持 `GEOMETRICALLY_FEASIBLE`，箱子集合和坐标布局不变。同一份布局在
`path_gate_mode: hard` 下也能通过全部门禁并得到 0 风险；默认仍保持 `score_only`。

## 失败策略

`path_gate_mode: score_only` 时，下降和斜向推进风险永远不会阻止执行文件生成。
以下核心错误仍会导致规划失败：

- 非底层箱找不到直接支撑。
- 箱子 ID 缺失或重复。
- 位置、尺寸或吸盘矩形缺失/非法。
- 坐标、尺寸、吸盘矩形或托盘尺寸包含 NaN/Infinity，或者实物箱体越过托盘边界。
- 在配置时间内找不到满足凹坑判定的执行顺序。
- 排序后的逐箱回放发现支撑、局部低层完成或凹坑判定不成立。

`path_gate_mode: hard` 时，垂直下降和斜向推进恢复为严格门禁；若同时启用
`force_publish_on_gate_failure`，完整路径门禁失败后仍按核心两阶段顺序生成受控降级
结果。三份文件从同一份 execution 报告派生，不会为 WCS 再规划一次。

以下基础错误即使启用强制发布也会拒绝：箱子 ID 缺失或重复、坐标或尺寸非法、箱子
越过托盘边界、非底层箱没有直接支撑、支撑拓扑成环，以及强制顺序本身无法满足
保留的支撑/局部低层完成依赖或凹坑规则。控制器始终必须执行自身路径规划和碰撞
检查。`hard` 模式出现 `forced execution order` warning 时，表示该托盘没有通过离线
路径门禁；`score_only` 模式出现该 warning 时，表示首次核心规划失败后使用了强制
核心排序，不代表软路径风险评估失败。

## 现场参数设置与故障调整

现场参数应按“先验证顺序，再测量误差，最后加入安全余量”的方式设置。不要在一次
测试中同时大幅调整多个参数，否则无法判断具体是哪种下降路径导致冲突。

### 推荐配置档位

| 场景 | `coordinate_tolerance_mm` | `box_xy_clearance_mm` | `suction_xy_clearance_mm` | `suction_z_clearance_mm` | `require_suction_pose` |
|---|---:|---:|---:|---:|---|
| 接口和顺序验证 | `0.000001` | `0` | `0` | `0` | `true` |
| 空箱低速初测 | `0.000001` | `1` | `2` | `2` | `true` |
| 按现场测量值运行 | `0.000001` | 按箱体 XY 误差计算 | 按吸盘/腕部外廓计算 | 按 Z 误差计算 | `true` |

“空箱低速初测”档位只是在没有测量数据时用于发现干涉的起始值，不应直接作为正式
生产参数。正式参数必须根据机械臂、吸盘、箱体和视觉/定位系统的实测最大误差确定。

定向推进参数必须和机器人控制器的实际路径一致：

| 场景 | `approach_offset_x_mm` | `approach_offset_y_mm` | `approach_z_clearance_mm` | `approach_box_xy_clearance_mm` | `approach_suction_xy_clearance_mm` |
|---|---:|---:|---:|---:|---:|
| 当前交付配置 | `20` | `20` | `20` | `0` | `0` |
| 现场低速初测 | 实测 X 推进分量 | 实测 Y 推进分量 | 实测预放高度差 | `0` 起逐步增加 | `2` 起逐步增加 |
| 按现场测量值运行 | 实测 X 推进分量 | 实测 Y 推进分量 | 实测预放高度差 | 箱体推进误差上界 | 吸盘/腕部推进误差上界 |

不要用增大安全余量代替错误的推进位移。应先测量预放点到目标点的 X/Y/Z 差值，
再分别设置 offset 和 clearance。历史诊断中，668 箱样例在旧偏移和安全余量组合下
曾在 `hard` 模式形成依赖环；当前默认使用 `score_only`，参数调整为 `20/20/20/0` 后
只用于风险诊断，不阻断规划。正式现场值仍应以机械臂实测轨迹为准。

### 按现场问题调整

| 现场现象 | 调整方案 |
|---|---|
| 箱体下降时擦碰旁边箱子 | 每次将 `box_xy_clearance_mm` 增加 `1～2 mm`，重新生成方案后测试。 |
| 箱体不碰，但吸盘、法兰、腕部或管路碰箱 | 每次将 `suction_xy_clearance_mm` 增加 `1～2 mm`。 |
| 吸盘接近目标箱顶时碰到旁边较高箱子 | 每次将 `suction_z_clearance_mm` 增加 `1～2 mm`。 |
| 实际推进方向或距离与规划模型不同 | 先停机测量预放点到目标点的 X/Y 分量，修正 `approach_offset_x_mm` 和 `approach_offset_y_mm`。 |
| 箱体在斜向推进或最终下降时擦碰 | 每次将 `approach_box_xy_clearance_mm` 增加 `1～2 mm`。 |
| 吸盘、法兰或腕部在斜向推进时擦碰 | 每次将 `approach_suction_xy_clearance_mm` 增加 `1～2 mm`。 |
| 机器人先在高处推进再下降 | 将实测推进平面与目标放置高度的差写入 `approach_z_clearance_mm`。 |
| 机械臂实际 XY 落点存在固定偏差 | 先标定机械臂，再把标定后的最大残余误差计入箱体和吸盘 XY 余量。 |
| 算法提示箱子悬空，但确认只是坐标小数误差 | 检查坐标输出精度，只将 `coordinate_tolerance_mm` 提高到 `0.001` 或 `0.01`。 |
| 提示缺少 `suction_rect_*` | 修复吸盘字段生成，不建议将 `require_suction_pose` 改为 `false`。 |
| `score_only` 下增加余量后风险数上升 | 查看 `execution_sequence_diagnostics.soft_path_risks`，结合现场轨迹标定；风险只记录，不改变顺序。 |
| `hard` 下增加余量后提示依赖环或不生成 execution 文件 | 当前名义路径模型无法在该余量下仅靠换序执行；核对参数是否与实测轨迹一致，必要时重新规划箱子位置。 |
| 箱子被放进凹坑，预放下降时吸盘碰已放箱 | 确认 `pocket_rule: approach_directional` 且 `preserve_open_direction: true`；检查 `origin` 与机械臂实际站位一致。 |
| 机械臂换到另一侧站位 | 同时修改 `origin`，凹坑判定方向会随之翻转，不要只改 `robot_reference`。 |
| `soft_path_risks` 里出现 `box pre-position descent` | 该箱的接近侧邻箱先被放置。核对 `side_neighbor_clearance_mm` 是否小于真实间隙，以及是否被 `open_corner` 旧规则放行。 |
| 某托盘第 2 箱仍然是上层箱 | 混高托盘的正常结果：地面邻箱比该上层箱底面更高，先放地面箱会把它永久封进凹坑，前瞻检查因此强制先放上层箱。查 warning 中该箱的 `open_direction` + `lookahead=true` 偏离记录。 |
| 想让垛型更早铺满地面层 | 调整 `sequence_planner.py` 的 `_TIER_WAVE_RINGS`（当前 `2`）。加大该值会推迟全部上层箱；它不是配置项，改动后必须重跑 11 托盘风险回归。 |

### 现场测量后的计算方法

```text
box_xy_clearance_mm
= 箱体最大水平摆动或偏移 + 预留安全量

suction_xy_clearance_mm
= 最大 XY 定位误差
  + 吸盘、法兰或腕部超出 suction_rect 的距离
  + 预留安全量

suction_z_clearance_mm
= 最大 Z 定位误差
  + 吸盘压缩量或箱体变形量
  + 预留安全量

approach_offset_x_mm / approach_offset_y_mm
= 预放点到目标点的实测水平位移分量

approach_box_xy_clearance_mm
= 推进阶段箱体最大水平摆动或定位误差 + 预留安全量

approach_suction_xy_clearance_mm
= 推进阶段末端外廓误差 + 预留安全量
```

在没有企业安全规范给出其它要求时，预留安全量可以先取 `1～2 mm`，再根据空箱
低速测试结果调整。所有 XY 余量均表示“每侧扩大”：例如配置为 `5`，检查区域的
总长度和总宽度各增加 `10 mm`。

### 参数安全限制

- `coordinate_tolerance_mm` 只用于几何计算精度，不能用于补偿机械臂误差。正常应
  保持 `0.000001`，不建议超过 `0.1 mm`。数值过大可能把悬空、越界或微小重叠
  误判为合法。
- 现场机械臂执行应保持 `require_suction_pose: true`。设置为 `false` 只适用于没有
  吸盘数据的离线分析，因为缺失吸盘矩形的箱子将跳过吸盘下降路径检查。
- `score_only` 下安全余量只改变风险诊断，不改变 `seq` 或发布结果；`hard` 下余量增大
  后出现依赖环，表示名义路径模型认为现有坐标布局不可执行。不得为了消除诊断或生成
  execution 文件而把参数降到低于现场实测误差的水平。
- `approach_offset_x_mm`、`approach_offset_y_mm` 和 `approach_z_clearance_mm` 必须
  描述机器人控制器实际使用的预放路径；路径模型不一致时，规划通过也不能证明现场
  无碰撞。
- `pocket_rule` 与 `origin` 必须同时描述同一个机械臂站位。`approach_directional` 只
  依赖偏移方向为正，与偏移数值无关；把它改成 `open_corner` 会重新放行接近侧邻箱
  已就位的放置，现场执行不允许这样设置。
- 每次调整配置后都要重新执行 `run_packing.py`，并使用同一时间戳新生成的
  `_execution.json`、`_execution_wcs.json` 和 `_execution_wcs_map.json`，不能混用
  不同批次文件。

## 现场测试建议

1. 先写入实测 `approach_offset_x/y_mm` 和 `approach_z_clearance_mm`；仅将
   `box_xy_clearance_mm`、`suction_xy_clearance_mm`、`suction_z_clearance_mm`、
   `approach_box_xy_clearance_mm` 和 `approach_suction_xy_clearance_mm` 设为低速测试
   起始值，验证 WCS `seq`、传送带顺序和机械臂目标箱映射。
2. 用空箱或替代箱测量实际预放点、推进 X/Y/Z 分量、定位误差和腕部/吸盘外廓。
3. 将测得的上界写入 `execution_sequence` 配置段后重新运行 `run_packing.py`。
4. 从混高托盘开始低速执行，记录每步目标坐标、实际坐标、报警和人工干预。
5. 任何碰撞、擦碰、压箱或顺序不一致都应停止该托盘测试，不允许现场临时跳序。
