# WCS 零尺寸输入过滤设计

## 目标

WCS 接口返回的库存记录若长、宽、高任一项小于等于 0，不得进入本地库存数据库或参与装箱；其余有效记录继续生成整批装箱结果。过滤是通用数据校验，不硬编码具体 `product_code`。

## 处理边界

接口 1 的完整响应仍先保存到 `packing-workspace/input/raw`，作为原始审计证据。程序完成 `case_type=MH423C` 筛选后、调用数据库同步前，对保留记录执行尺寸校验：

- `length > 0`
- `width > 0`
- `height > 0`

任一条件不满足即判为零尺寸/非法尺寸输入并剔除。

## 数据流

有效记录同时传给：

- `wcs_stock_box.sync_stock_entries()`，作为当前装箱库存；
- `wcs_stock_box_all.insert_new_stock_entries()`，作为有效库存历史。

非法记录不写入这两个表，也不传给 `stock_to_boxes()`。原始响应文件仍保留这些记录。

## 日志

每次拉取存在非法尺寸时，输出一条明确日志，包含：

- 忽略记录数量；
- 最多若干条样例；
- 每条样例的 `product_code`；
- `box_type`；
- `length × width × height`。

日志不得把过滤描述成装箱算法失败。

## 同步与恢复

当前数据库包含零尺寸记录时，启用过滤后的下一次拉取会得到更小的有效 `product_code` 集合，因此现有集合比较会触发 `wcs_stock_box` 全量替换和重新装箱。WCS 日后修正这些记录后，有效集合重新增加，对应记录会重新入库并再次触发装箱。

## 异常规则

- 缺失、空字符串、非数字以及非有限值均按非法尺寸处理。
- 单条非法记录不阻断整个接口批次。
- 如果过滤后没有有效记录，沿用现有防空包逻辑，不清空当前库存表。
- 不关闭输出质量门禁；门禁继续防止其它路径产生零尺寸输出。

## 测试

- 正常正尺寸记录全部保留。
- 任一维度为 0、负数、缺失、非数字或非有限值的记录被剔除。
- 过滤不会修改输入对象。
- `fetch_once()` 只把有效记录传给当前表和历史表仓库。
- 日志包含过滤数量与产品码。
- 全部非法时不会触发装箱。
