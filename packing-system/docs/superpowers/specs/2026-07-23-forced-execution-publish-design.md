# 门禁失败时强制发布执行顺序设计

## 目标

本版采用临时现场策略：启用执行顺序规划后，规划器先执行完整门禁；单个托盘因机械臂路径门禁、开放方向门禁、依赖成环或搜索超时失败时，仍为该托盘生成确定性的空间阶梯波顺序，并继续发布 `_execution.json`、`_execution_wcs.json` 和 `_execution_wcs_map.json`。

这项策略用于现场联调，不代表强制顺序已经通过机械臂路径安全验证。门禁误判及参数标定问题保留为后续改进项。

## 降级边界

正常路径保持现有全部检查。强制降级只绕过以下执行路径门禁：

- 箱体和吸盘的最终垂直扫掠；
- 预放位置下降和斜向推进扫掠；
- `max_occupied_directions` 与残余可完成性检查；
- 居中后的执行路径最终回放。

强制降级仍必须满足：

- 箱子 ID 存在且唯一；
- 坐标、尺寸和托盘尺寸有限且有效；
- 所有箱子位于托盘边界内；
- 支撑拓扑无环，上层箱不得先于直接支撑箱；
- 输入输出箱子集合守恒；
- `seq` 从 1 连续且唯一；
- 垛型按现有规则居中，并重新计算 `robot_depth` 和 `stack_height_before`。

若基础数据无效、箱子越界或支撑拓扑本身成环，不能构造物理上有意义的顺序，仍终止 execution 三件套发布。

## 顺序与发布

降级顺序复用当前有向空间阶梯波排序键，依赖图保留直接支撑边和已经确认的高度感知局部抬升/退出走廊边，并为降级过程使用新的独立时间预算。每个失败托盘单独降级，其他托盘继续使用完整门禁验证通过的顺序。

规划器必须在日志中记录托盘 ID 和原始门禁错误，并明确标记该托盘使用了强制顺序。WCS 接口不新增字段，避免改变现场协议。

执行报告只规划一次。`_execution.json`、WCS cases 和 WCS map 均从同一份执行报告派生，禁止 WCS 导出再次对原报告重新规划。三份文件中的 `seq` 必须一致；`stack_height_before` 仍只保留在 `_execution.json`。

## 配置

新增 `execution_sequence.force_publish_on_gate_failure` 布尔参数。本版交付配置设为 `true`。设为 `false` 时恢复原有行为：任一托盘未通过门禁即不发布 execution 三件套。

## 验证

- 完整门禁通过时不触发降级，输出与现有行为一致。
- 构造路径依赖环时，启用开关仍生成三件套，且顺序满足支撑拓扑。
- 关闭开关时，同一依赖环继续抛出 `ExecutionSequenceError`。
- 无效 ID、越界或支撑环即使启用开关也拒绝发布。
- execution、WCS cases 和 map 的箱子集合及 `seq` 一致。
- `stack_height_before` 只存在于 `_execution.json`。

## 已知风险与后续项

强制顺序绕过的门禁原本用于近似机械臂下降、推进和抬升包络，因此该顺序必须由现场机械臂控制器继续完成自身路径规划和碰撞检查。后续应实现高度感知的局部抬升/退出走廊，并重新标定吸盘安全余量、预放偏移和推进高度，减少误判后再取消强制发布策略。
