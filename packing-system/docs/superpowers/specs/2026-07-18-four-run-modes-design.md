# 四种运行方式下拉框设计

## 目标

用一个“运行方式”下拉框替换现有“接口模式”复选框，统一提供四种业务运行方式，并新增“接口运行至成功”。装箱核心算法保持不变；仅修改 UI、WCS 服务调度层和对应测试。

## 四种运行方式

1. **接口持续运行**：按设置间隔循环拉取；有新数据时计算并输出；持续运行直到用户停止。
2. **接口单次运行**：拉取一次；有新数据时计算输出一次；无新数据时提示后停止。
3. **Excel 单次运行**：选择 Excel，调用现有 `run_packing.py` 计算输出一次。
4. **接口运行至成功**：循环拉取；有新数据时计算并输出；某轮出现至少一个 `mpm_status == "SUCCESS"` 的托盘后立即停止，即使同轮仍有失败托盘。

默认选择“接口持续运行”。

## 下拉框与控件联动

| 运行方式 | 拉取间隔 | 选择 Excel | 停止按钮 |
|---|---|---|---|
| 接口持续运行 | 启用 | 禁用 | 运行时启用 |
| 接口单次运行 | 禁用 | 禁用 | 运行时启用 |
| Excel 单次运行 | 禁用 | 启用 | 运行时启用 |
| 接口运行至成功 | 启用 | 禁用 | 运行时启用 |

“一键装箱”按钮保留；提示、步骤状态和日志使用当前运行方式与实际拉取间隔。

## 服务调度

`packing/run_wcs_service.py` 增加统一 CLI 参数：

- `--run-mode continuous` → `WcsPackingService.run_loop()`
- `--run-mode once` → `WcsPackingService.run_once()`
- `--run-mode until-success` → `WcsPackingService.run_until_success()`

Excel 模式继续调用 `packing/run_packing.py`，不经过 WCS 服务。

## 运行至成功流程

1. 调用接口拉取库存。
2. 如果没有新插入数据，等待设置间隔后继续拉取，不对相同库存重复计算。
3. 如果有新数据，读取未达标库存，执行现有工作流并保存完整结果。
4. 统计本轮报告中 `SUCCESS` 托盘数量。
5. 数量大于零时输出成功停止标记并结束服务；否则等待下一轮。
6. 拉取或计算异常时记录错误，等待下一轮继续；用户停止时立即退出。

## 服务结果边界

为避免通过日志文本猜测成功状态，`pack_once()` 返回一个小型调度结果对象，至少包含：

- 是否执行了计算；
- 本轮成功托盘数量；
- 本轮报告路径。

这个对象只属于 WCS 服务调度层，不进入装箱算法。

## UI 后台进程

- 下拉选项映射到 `continuous`、`once`、`excel`、`until-success`。
- 接口模式启动 `run_wcs_service.py --run-mode <mode>`。
- Excel 模式启动现有 `run_packing.py --config ... --out ...`。
- WCS 服务继续通过 `[UI-RESULT] <path>` 通知 UI 加载每轮结果。
- “运行至成功”结束前输出明确日志，UI 在进程正常退出后显示完成状态。

## 验收标准

1. 原接口复选框消失，顶部出现含四个选项的运行方式下拉框。
2. 默认选中“接口持续运行”。
3. 拉取间隔和 Excel 按钮按表格正确联动。
4. 三个 WCS CLI 模式路由正确。
5. “运行至成功”无成功时继续、有成功时停止；成功与失败共存时仍停止。
6. 无新数据时不重复计算。
7. Excel 单次模式行为保持不变。
8. UI、WCS 服务和算法回归测试通过。
9. `packing/src/main`、`packing/src/packing`、`packing/src/rescue` 未修改。
