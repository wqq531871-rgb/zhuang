# 箱数卡片上移与运行依赖补齐设计

## 目标

把右侧“规则箱子数目”和“不规则箱子数目”移动到当前托盘标题下方、填充率和指数上方，与用户截图顶部红框一致。同时检查实际启动解释器的运行依赖，安装确认缺失的包。

## UI 设计

沿用现有两个 `MetricCard` 实例、统计函数和刷新生命周期，只调整右侧指标网格顺序：

1. 第 0 行：规则箱子数目、不规则箱子数目。
2. 后续行：填充率、指数、综合评分、稳定等级、箱子数量、总重量、高度利用率、平均支撑率。
3. 最后一行左侧：重心偏移；右侧保持空白。
4. “操作建议”和“风险与异常”继续位于全部指标卡下方。

不复制卡片，不增加新的统计状态，避免两处显示不同步。

## 依赖审计与安装

实际启动解释器为 `D:\Python\python.exe`，Python 版本为 3.11.4。导入审计确认缺少：

- `pyqtgraph==0.13.7`：三维控件。
- `PyOpenGL==3.1.7`：OpenGL 渲染后端。
- `PyMySQL==1.0.2`：数据库功能。
- `ortools==9.8.3296`：主装箱算法求解器，缺失时算法会降级。
- `protobuf==4.25.3`：满足 OR-Tools，同时兼容同一解释器中的 TensorFlow 2.13。

最初安装 `ortools==9.12.4544` 会要求 `protobuf>=5.29.3`，与同一解释器中的 TensorFlow 2.13 冲突。代码只使用稳定的 `CpModel`、`CpSolver`、`OPTIMAL` 和 `FEASIBLE` API，因此改用兼容的 OR-Tools 9.8。现有 NumPy、Pandas、PyQt5、OpenPyXL、PyYAML、Requests、FastAPI、Uvicorn 和 Pydantic 均可导入。只补装缺失包，不按旧版 Python 3.8 requirements 降级现有数值库。

## 验证

- UI 测试比较卡片纵坐标，确保规则/不规则卡片位于填充率和指数上方。
- 两张卡保持同一行，规则卡在左、不规则卡在右。
- 逐个导入四个新增依赖。
- 导入 `pyqtgraph.opengl`，并确认界面模块的 `HAS_GL` 为真。
- 运行箱数统计和 UI 回归测试、Python 编译检查及 V3 离屏界面烟测。
