# 前端成功托盘总数卡片与拉取间隔设置

## 目标

仅修改 PyQt 前端界面，不修改 `packing/src`、装箱流程或核心算法。

## 界面设计

- 保留左侧概览区现有“成功托盘”小卡片。
- 在“平均填充率”下方、“高级参数”上方新增一张横向大卡片，标题为“成功托盘总数”。
- 新卡片显示完整结果中 `mpm_status == "SUCCESS"` 的托盘数量，不受状态筛选、订单筛选、搜索或分页影响。
- 在顶部“接口模式”复选框右侧增加“拉取间隔”数字输入框，单位为秒。
- 输入范围为 `1–86400` 秒；默认读取基础 YAML 的 `data_source.download_interval`，缺失或无效时使用 `200` 秒。
- 非接口模式下禁用拉取间隔输入框，接口模式下启用。

## 数据流

- 成功托盘总数直接从前端已加载的 `pallets` 列表计算，不新增后端字段。
- 启动接口模式时，前端把输入框数值写入本次生成的临时 YAML：`data_source.download_interval`。
- 界面运行状态和日志使用实际设置值，不再显示写死的“200 秒”。
- Excel 单次装箱模式不使用该设置。

## 代码范围

- `ui/realtime_dashboard_v2.py`：新增横向指标卡片，并在结果加载、清空时更新它。
- `ui/realtime_dashboard_v3_clean.py`：新增拉取间隔控件、临时配置写入和动态提示。
- `ui/tests/`：增加前端行为测试。
- 明确不修改 `packing/src/`、`packing/run_packing.py` 或算法配置实现。

## 错误处理

- 输入框本身限制数值范围，避免生成非法间隔。
- 基础 YAML 中间隔缺失、无法转为整数或越界时，前端回退为 `200` 秒。
- 临时配置仍沿用当前 YAML 生成与异常提示流程。

## 验收标准

1. 原“成功托盘”卡片仍存在。
2. 红框位置出现横向“成功托盘总数”卡片，并显示全局成功数量。
3. 顶部出现拉取间隔秒数框，范围 `1–86400`。
4. 默认值来自基础配置，缺失或无效时为 `200`。
5. 接口模式临时 YAML 使用用户设置的间隔。
6. 界面提示和日志显示实际间隔。
7. 前端测试与现有算法测试通过，`packing/src` 没有修改。
