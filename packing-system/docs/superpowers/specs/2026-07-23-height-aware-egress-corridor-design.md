# 高度感知的局部抬升与退出走廊设计

## 目标

所有托盘继续使用同一套有向空间阶梯波。规划器不要求整层完成，也不通过简单调整 `support_tier` 排序键延后所有上层箱，而是只延后会高出后续局部表面并占用机械臂抬升或退出走廊的上层箱。

托盘 1 的局部顺序应由 `1,2,3,4,5` 调整为 `1,3,4,5,2`。托盘 11 中，远端上层箱顶面与后续底层箱顶面同高时不增加延迟边，允许远端柱继续适时生长。

## 几何定义

对待放箱 `L` 和已经具有直接支撑、支撑层级更高的候选箱 `U`，计算：

```text
L_top = L.z + L.height
U_top = U.z + U.height
```

只有 `U_top > L_top + side_height_tolerance_mm` 时，`U` 才可能阻挡 `L` 放置后的抬升或退出。

走廊由两部分组成：

1. 局部抬升区：`L` 的实际吸盘矩形；缺少吸盘矩形且配置允许缺失时使用箱体矩形。矩形四周按 `side_neighbor_clearance_mm` 扩张，覆盖紧邻和斜对角邻箱。
2. 定向退出区：将同一矩形从目标位置沿 `+X/+Y` 平移到 `approach_offset_x_mm/approach_offset_y_mm` 定义的预放位置，使用现有精确线段-Minkowski 相交算法计算扫掠区。

如果 `U` 的箱体投影进入任一走廊，增加硬边 `L -> U`。该边只从较低支撑层指向较高支撑层，因此不会因自身形成逆向支撑环。

## 调度与回放

高度走廊边与直接支撑边、垂直扫掠边和斜向推进边一起进入拓扑调度。软排序键继续使用现有空间阶梯波，不改成整层优先。

最终居中后重新构建高度走廊边并回放，确保平移没有改变判定结果。扫描偏离日志继续使用 `hard_dependency`，不增加 WCS 字段。

门禁失败强制发布时仍保留直接支撑边和高度走廊边，只绕过其余可能误判的路径门禁及开放方向门禁。这样强制顺序仍符合本次选定的局部延迟规则。

## 配置

不新增高度走廊专用参数。复用：

- `side_neighbor_clearance_mm`：局部抬升和退出走廊的 XY 余量；
- `side_height_tolerance_mm`：比较 `U_top` 与 `L_top`；
- `approach_offset_x_mm`、`approach_offset_y_mm`：退出方向和距离；
- `require_suction_pose`：吸盘矩形缺失时是否拒绝规划。

## 验证

- 托盘 1 形状中，三个邻近底层箱都先于远端上层箱。
- 同样布局中，将上层箱顶面降到后续底层箱顶面容差内时，不增加延迟边。
- 远离局部抬升区且不在 `+X/+Y` 退出扫掠区的上层箱不被延后。
- 定向退出扫掠命中但局部矩形不相邻时，仍增加延迟边。
- 不同配置原点只改变空间波方向，不改变机器人位于 `x_max/y_max` 一侧的退出方向。
- 真实 668 箱输出保持箱子守恒、连续唯一 `seq`，并验证托盘 1 和托盘 11 的关键相对顺序。
