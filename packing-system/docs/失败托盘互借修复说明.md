# 失败托盘互借修复（凑标 + 合并装满 + 指数互换 + 指数再分配 + 装满压实）说明

> 位置：`src/rescue/rescue_optimizer.py`（`RescueOptimizer.optimize_failed_by_failed`）
> 与 `src/rescue/index_swap.py`（指数互换）。
> 接入点：baseline 救援链末尾 + GCP 路径收尾（`src/main/workflow.py`），两条路径都生效。
> 专项测试：`tests/test_rescue_consolidation.py`（8 项）、`tests/test_index_swap.py`（3 项）。

## 1. 问题背景（修复前）

- `optimize_failed_by_failed` 历史上是**空实现**：`enable_expensive_repack` 默认
  False 直接返回 `rescued=0`，开了开关也只有 TODO 注释——"失败托盘互借修复成功 0"
  是必然输出；
- 其余"装满"类救援器选择门槛极窄（低载 ≤5 箱、fill<0.12 尾盘等），重建又只会铺
  单层地板 → 盘数更多被棘轮拒绝；
- GCP 路径根本没有救援链；
- 结果：真实 5000 箱订单的失败盘平均填充率只有 ~0.41-0.56，最低 0.07，
  明显没有"尽量装满"。

## 2. 现在的机制

对每个 `(托盘类型, 订单[, case_group])` 分组，在所有指数救援尝试完成后：

### 2.0 指数互换（先行，`src/rescue/index_swap.py`）

把**富余成功盘**（mpm > target，配方/beam 装满路径产出）的高指数箱与失败盘
的低指数箱互换：成功盘保持 ≥ target，失败盘凑到 target。数学边界：两盘互换
指数守恒，能净注入失败盘的指数 ≤ 组内成功盘总富余 σ——σ=0（如 GCP 精准
192 盘）时数学上不可换，诊断行如实给出 `swap_surplus_total`。

- 外科手术式：只摘"上方无箱"的箱，在**既有布局**上用增量候选生成器
  （与 hole_fill 同源，含吸盘位姿）插入换入箱，不做整盘重装；
- 候选偏好"接收盘净腾空间"（换出低指数大箱、换入高指数小箱——指数密度
  再分配），插入失败自动尝试下一候选组合；
- 验收：双盘全量门禁（带 target，达标盘免 gap）+ 重心 + 两盘箱子并集守恒 +
  双双达标，全过才提交；预算：单组 30s / 最多 8 次。

### 2.1 进池

全部 FAILED 且填充率 < 0.92 的托盘（≥0.92 视为已够满不动；
单组箱数上限 2000，超限优先收最空的盘）。

### 2.2 凑标局部提交（`_extract_commit`，2026-07-10 重构为独立提交）

在失败池上**重跑配方规划器**（`recipe_planner.plan_recipe_pools`：整层+顶带
枚举、库存约束下最大化达标实例数），每个实例用初装同源的
`recipe_first._pack_instance` 实装（整池装入 + 达标 + 整盘门禁）——把失败池
里凑得出目标指数的箱子组合先提成达标盘。初装时配方只跑一次，救援阶段的
残池构成已完全不同，重规划常能挖出新达标盘（这是"指数分配"问题的主修复）。

**局部提交**：实例箱子先重映射到尽量少的源托盘（同尺寸/重量/指数/小箱标记
的箱子可互换，`_cluster_instance_boxes` 贪心聚拢），凑出的达标盘**立即
提交**——只重排受影响的少数源托盘的剩余箱（池小、秒级、与机器速度无关），
其余失败盘原样不动。独立棘轮：守恒 + 门禁 + 新增达标 + 失败盘数不增。

> 重构动机：旧实现把凑标和全池合并绑在同一个候选里做全有全无验收，而
> 合并重装耗时在预算刀口上（同一台机器冷/热 78s vs 131s、慢 2.5 倍的机器
> 必超时）——超时降级的碎盘候选被棘轮拒绝时，凑标成果被连坐丢弃，达标数
> 随机少 2-3 且跨机器不可复现。拆分后凑标增益结构上不受合并耗时影响：
> 同一状态三次重放逐位一致（+1 提交 18s + 合并 +1 45s）。

### 2.3 装满合并（`_repack_pool`，凑标提交后的剩余失败盘，独立棘轮）

- ≤60 箱小池：`PoolCompactor` 快路径；
- 大池按体积降序逐盘装，候选：整层格栅（全窗口 `prefer_fill`，填充率 ≥0.85
  时**短路**省掉 beam）/ 整层格栅（同底面最大组，几何可达 target）/
  beam(None) 纯装满 / beam(target)（仅剩余池指数仍够一个达标盘时跑）；
  选择时**达标候选优先**（其中取装入体积最大），否则纯体积最大；
- 全空时居中单箱兜底（重心安全），保证守恒不断裂；
- 收尾**尾盘二次压实**：填充 < 0.55 的盘并池重装，严格更少盘才替换；
- **提前放弃**（原方案零改动）："无改进可能"（达标产出不可能超过基线 +
  剩余池指数凑不出达标 + 盘数不可能更少）——诊断行
  `aborted_no_improvement_possible`，把时间留给有希望的组；
- **超预算降级收尾（2026-07-10 慢机器修复）**：单组墙钟预算（90s）耗尽
  **不再整体放弃**（旧实现超时直接 `return None` 丢弃全部成果），而是
  降级为快速路径（整层格栅 + 单箱兜底，不跑 beam）收尾；降级中连续 3 轮
  装不进 3 箱以上则**徒劳中止**（碎片化候选反正过不了棘轮，不再空耗）。
  合并被拒只损失装满收益，凑标达标盘已在 2.2 节独立提交、不受影响。

### 2.4 棘轮验收（全部满足才原地替换，否则原方案零改动）

- 箱子守恒（id 多重集完全一致）；
- 新盘逐盘过全量约束门禁（带 target：达标盘免 gap；支撑/吸盘/小箱/重心
  恒查，与流水线同源）；
- 盘数严格变少，**或** 新增达标盘且失败盘数不增加
  （防"+1 达标"以摊出更多低填充碎盘为代价）。

高填充（≥0.80）SUCCESS 盘绝不进池；指数互换只在双双达标时才触碰成功盘；
低填充达标盘仅经 2.5 节的独立棘轮参与再分配。全链条达标数只增不减。

### 2.5 指数再分配（`_redistribute`，互借修复之后）

针对"填充率 70% 就达标"的盘（高指数密度小箱被初装错配集中）：把
**填充率 < 0.80 的达标盘"溶解"**（≤ min(4, 失败进池盘数)，最空优先），
和失败盘的低指数箱一起重跑配方规划——高密度箱型给整层枚举提供新的
组合选择（如高密度顶带 + 低密度整层 = 达标），同样的总指数凑出更多
达标盘。两道廉价预判不过即秒退，绝不烧无谓时间：

1. **规划预判**：`plan_recipe_pools` 只规划不实装（秒级）；
   规划实例数(溶解池) − 溶解数 > 规划实例数(纯失败池) 才开工；
2. **实装预判**：凑标实装出的达标盘数 ≤ 溶解数即放弃
   （`extraction_below_baseline`，省掉注定被棘轮拒绝的装满验证）。

独立棘轮（基线 = 溶解数）：新达标数不低于基线且（盘数更少 或 新达标数
严格超基线且失败盘不增）才接受——**溶解的达标盘绝不净亏**。独立预算
60s。诊断行：接受打印 `指数再分配：溶解低填充达标盘 k ...`；未接受打印
`指数再分配诊断：未接受（原因）`。

数学边界（诚实）：溶解不创造指数，净增达标要求
`失败池总指数 + 溶解盘富余 ≥ 目标指数`；它解锁的是**几何**——失败盘
的富余体积（fill 60-70%）× 达标盘的富余密度重新组合。构造用例
（tests/test_rescue_consolidation.py::test_redistribute_low_fill_success）
验证净增：1 个 23% 填充达标盘 + 3 个几何锁死失败盘 → 3 盘全达标（净 +2）。

### 2.6 装满压实（`_fill_compact`，2026-07-11 新增，救援链末位 + 跨子组收尾）

针对报告中残留的碎片失败盘（如 fill 0.07 的 14 箱盘与 fill 0.64 的盘共存）：
2.3 节的整池合并是**全有全无**验收——大池超预算被拒、或按"+1 达标"分支
验收（允许盘数不减）后，明显可并的碎盘会原样留下。本阶段做最便宜的
纯装满兜底，按填充率升序逐个处理最空失败盘：

1. **两两合并（2 盘→1 盘）**：找体积上装得下它全部箱子的搭档盘（合并
   后填充 ≤ 0.92，超过实际装不出），最空搭档优先（首个搭档即命中 →
   秒级、与机器速度无关）。单对尝试三条通道递进：
   PoolCompactor 行式列摆放（≤120 箱，毫秒级）→ **CP-SAT 精确摆柱**
   （复用 GCP 落地原语；柱底面积预判不可行秒退。大底面混柱贪心摆不开、
   精确解能开——实测 2 大箱碎盘 + 12 箱半满盘这类案例只有它能并）→
   整层格栅 + beam（≤60 箱小池）。
2. **吸收溶解**：单一搭档装不下整盘时（碎盘是几个大箱、各搭档只剩零散
   空间），把碎盘箱子**分摊**进多个搭档盘（≤6 个、≤3 轮、每盘重装须
   保留搭档全部原箱且至少吸收 1 箱），全部吸干才提交（盘数-1）。仅对
   真碎盘（fill < 0.55）开，中填充盘整盘摊出去的富余空间几乎不存在。

每次合并独立提交（守恒 + 全量门禁 + 严格减盘），任何一次失败不影响
其它；不动达标盘、不产生新达标诉求（合并盘仍 FAILED），纯减盘数、提
填充。预算 20s/组（`FILL_COMPACT_BUDGET_S`）。

**跨子组收尾（`workflow._cross_group_fill_compact`）**：组内子聚类
（`__SPLITREST__`）把同一真实订单拆成"规则子集 + 杂箱组"两个内部子组，
各子组救援链互相看不见对方的失败盘——碎盘可能与可行搭档被人为隔开
（实测：fill 0.07 碎盘在 4 盘杂箱组里无搭档，可行搭档全在主组）。所有
分组完成后按真实订单重聚（case_group 标签保留，业务隔离不破坏）再补
一次装满压实，并同步受影响子组统计。公开入口
`RescueOptimizer.fill_compact`（`run_packing._DynamicRescueOptimizer`
同名转发）。

test_case_group / test_rescue_consolidation(8) / test_index_swap / test_geometry /
test_incremental / test_recipe_planner / test_constraint_config /

指数互换在上述两个数据集上 0 提交，原因是硬边界而非缺陷：组内成功盘富余
σ≈0~26 且顶层可摘的高指数箱盖不住失败盘缺口（诊断 `swap_surplus_total` /
`swap_reason` 可见）；构造用例（tests/test_index_swap.py）验证了机制端到端
可用——任何"配方/beam 装满出富余成功盘 + 失败盘差一点"的订单都会受益。

## 4. 已知局限（诚实边界）

- **6mm 间隙规则已改为锚定语义（2026-07-09）**：旧实现要求四方向最近正
  间隙全部 <6mm，会误杀"贴紧一侧后对面残余不可避免间隙"的合法摆放（行尾
  残缝、混底面槽位残缝）。新语义：X、Y 每轴贴紧一侧邻箱或托盘边即通过，
  浮空（两侧均不贴紧）仍拒绝，是旧规则的纯放宽。消融对照（同代码只换 gap
  语义）：达标数不变（chain 140±1 / 5000 143，差异在已知 CP-SAT ±1 波动
  内）——gap 不是达标的绑定约束，达标缺口在指数分配而非间隙几何；收益在
  失败盘更少更满（5000 失败盘 40→31、总盘 183→174；chain 151→149，
  MN01S 组失败盘填充 avg 0.60）。混底面"粉尘尾盘"压不进体积下界时棘轮
  仍如实拒绝（诊断行 `not_better`），此时是箱型组合的真实几何极限而非
  gap 规则所致。
- 尾盘压实后仍可能存在个别低填充盘（如 0.06）：那是"新达标盘拿走了指数密集
  箱"之后的真实残渣，失败盘数已不增加。
- **"填充率低 ≠ 一定可合并"（装满压实的几何边界，附实测反例）**：
  ①高度量化——512×417×365 箱两层 730 > 盘高 720，注定单层，盘数由
  **底面积**而非体积决定：两个 fill 0.42 盘的柱底面积合计 = 1.40 倍盘面，
  2→1 物理不可行（concentrated MZ06S 0.418+0.423 对）；②底面网格上限——
  370×780×320 箱每盘几何上限 12 个（3×2 × 2 层，beam 实证 13/14 必剩），
  含 12 个该箱型的盘 fill 仅 0.48 但已是该箱型满盘；③高密拼盘——
  fill 0.18 碎盘的两个搭档已 0.75/0.78，两两合并需单盘 0.93+、3→2 需
  平均 0.86 填充，超混箱实际装载上限（chain MZ06S-60，全部通道实测
  不可行）。这些残留经 CP-SAT 精确摆柱确认无解后如实保留。
- 互借修复耗时与失败盘规模成正比（5000 最大组 ~3 分钟）；可通过
  `PACK_CANDIDATE_WINDOW`（默认 240）和 beam 参数调速。
- **跨机器差异（诚实说明）**：绝对耗时与机器算力成正比（实测同代码同数据
  在另一台机器上 packing 阶段慢约 2.5-3 倍）；CP-SAT 的墙钟时限
  （`_ILP_TIME`/`_CPSAT_TIME`）使个别分组在慢机器上从"GCP 成功"翻转为
  "爆盘回退 baseline"，初装达标随之 ±1（已记录的已知限制）。凑标局部提交
  与各棘轮阶段的**达标增益**与机器速度无关；墙钟预算
  （`EXTRACT_COMMIT_BUDGET_S=60 / CONSOLIDATION_TIME_BUDGET_S=90 /
  REDISTRIBUTE_TIME_BUDGET_S=60`，类常量可调）只影响装满/合并等
  机会性收益的命中率。
- 诊断：每组都会打印——凑标提交
  `失败托盘互借修复（凑标提交）：新增达标 X，受影响 Y 盘重排为 Z 盘`；
  合并接受时 `失败托盘互借修复：X 盘(a%) 合并重装为 Y 盘(b%)，新增达标 Z`；
  未接受时 `失败托盘互借诊断：未合并（原因）`；再分配
  `指数再分配：…` / `指数再分配诊断：未接受（原因）`；装满压实
  `失败盘装满压实：合并/吸收 X 次（纯减盘数）` /
  `跨子组装满压实（托盘类型 / 订单）：合并 X 次`。原因含
  `less_than_2_consolidatable / already_compact_no_success_potential /
  not_better / box_conservation_failed / constraint_gate_failed /
  no_planned_gain / extraction_below_baseline / no_mergeable_pair` 等。
  JSON 统计在 `by_pallet_type.*.kpi.consolidate_* / extract_commit_success /
  redistribute_* / fill_compact_*`。
